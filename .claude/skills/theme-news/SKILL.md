# テーマ急上昇ニュース調査

market_data.html の上位3テーマについて、急騰・急落の理由を WebSearch で調査し推察する。要約をデイリー保存し直近1ヶ月分を次回コンテキストに使う。

## 基本方針

**「アクター × シグナル」で網羅的に洗う**。テーマ名そのままのクエリだけだと必ず見逃す。発信者（アクター）は限られており、各アクターを1回以上検索すれば取りこぼしを構造的に防げる。**1クエリに複数アクターを混ぜると有名な1件に引きずられる** ので、アクター別に独立で検索する。

### アクター階層（株価インパクトが大きい順）

| 記号 | アクター | 内容 |
|---|---|---|
| A | 政治 | 首相・担当大臣・与党幹部・閣議 |
| B | 行政 | 担当省庁・審議会・検討会 |
| C | 海外 | 海外政府の類似政策、関税、地政学、同業国動向 |
| D | 企業 | 個別決算・業績修正・提携・受注・新製品 |
| E | 相場 | 地合い、セクターローテーション、資金フロー (手順3で代替) |

### シグナル語彙（クエリに織り込む汎用語）

時代・政権が変わっても機能する具体名を含まない語:

- **介入**: 「国が前に出る」「全面支援」「基幹戦略」「経済安保」
- **制度変更**: 「法改正」「閣議決定」「行動計画」「規制緩和/強化」
- **数値コミット**: 「◯兆円」「◯年まで」「◯%目標」
- **公人発言**: 「表明」「発言」「会見」「指示」
- **国際連動**: 「米国/中国/EU」「関税」「輸出規制」

## 手順

### 1. 過去履歴 & カレンダー読み込み

**1-0. 今日の日付確定 (価格日基準)**:
手順内で使う「今日」はカレンダー日付ではなく shintakane システムの **価格日** (`ks_util.get_price_day()`、17:00 前は前日扱い) を使う。**手順2 以降の検索クエリ・履歴ファイル名・推察文中の日付・履歴保存ファイル名すべてに反映する**。実行時に下記の Bash 一行で取得して以降の処理で参照する (venv 必須、`scripts/` から実行):

```bash
source .venv/bin/activate && cd scripts && python -c "from ks_util import get_price_day; from datetime import datetime; print(get_price_day(datetime.now()).isoformat())"
```

理由: market_data.html は 18:00 以降に生成され翌日 0:00 台に実行されることがある。**カレンダー日付で「今日」とすると、5/19 大引け後に生成された market_data.html を 5/20 早朝に開いた場合「5/20 のデータ」と誤認**して翌営業日の動きとして語ってしまう。価格日基準なら同じ実行が 5/19 扱いになり、調査対象日と本文中の日付が一致する。

実装例 (時刻ごとの返り値):
- 5/19 23:50 実行 → `2026-05-19` (当日扱い)
- 5/20 00:40 実行 → `2026-05-19` (17:00 前なので前日扱い)
- 5/20 17:30 実行 → `2026-05-20` (17:00 過ぎで当日扱い)

**1-1. 過去履歴**:
`.claude/skills/theme-news/history/*.md` を Glob し、ファイル名 `YYYY-MM-DD.md` で **今日 (= 1-0 の価格日) から30日以内** のものだけ Read。テーマの継続性・推移把握に使う。存在しなければスキップ。

`.md.running` / `.md.done` / `.md.meta.json` は run_theme_news.py ラッパーが管理する補助ファイルで、**スキル側では一切参照・解釈しない**。特に `.md.running` は親ラッパー (= 自分を起動した親プロセス) が作ったロックなので、これを「並行する別セッションが走っている」と誤検出して中止しないこと。並行実行の制御はラッパー側の責務。

**1-2. 履歴の日付ギャップ検出**:
履歴最新日と今日の差で分岐する。

- 前営業日あり / 1営業日のみ欠落: 通常通り (手順4の「直近1週間」検索でカバー)
- 2営業日以上欠落: 手順4で空白期間カバー検索を追加
- 3営業日以上欠落 / 初回実行: 直近1週間を遡及検索

**1-3. 株カレンダー**:
`.claude/skills/theme-news/calendar.html` を Read。

- 「直近」「中期」のイベントは手順3 (マクロ) と手順5 (推察) で「あと N 日でこのイベント」のカウントダウンとして参照
- 「Past」は過去イベントの結果記録で必要時のみ参照
- ファイル不在ならスキップ (初回実行)

### 2. テーマランクデータの読み取り

`$KS_DATA_DIR/code_rank_data/market_data.html` を解析:

- `<h2>テーマランク</h2>` 後の `<div class="theme-grid">` 内 `<div class="theme-badge ...">` から、**ランク・テーマ名・騰落率・前日比ランク変動（↑N / ↓N / → / NEW）** を取得
- **上位3テーマ（#1〜#3）が調査対象**

**2-1. 各指標の意味**:

| 指標 | 内容 | 推察への使い方 |
|---|---|---|
| ランク | 株探テーマランキングの順位 + その日のモメンタム(順位変動量)を加算したスコアで再ソート。直近で順位を伸ばしたテーマほど上位 | 上位入り = 「現在進行形の急上昇」 |
| ランク変動 ↑N / ↓N / → | 当日モメンタム順位と前日モメンタム順位の差分 | テーマ自体への注目度の変化 (騰落率とは別軸) |
| NEW | 前日のランキングに無かったテーマが当日初登場 | 新材料発生のシグナル候補。リーダー株の動意を逆引き |
| 騰落率 | 当日のテーマ平均騰落率 | 株価モメンタム |
| `<small>[N]</small>` 構成銘柄数 | その日にシステムが取得・調査した銘柄数 (取得失敗・対象外・ETF除外等で日々変動) | **テーマの強さ指標ではない**。騰落率の振れ幅を解釈する補助情報のみ |

**構成銘柄数 [N] の解釈ルール**:
- N 大 (50以上) → 個別銘柄の影響が均される。騰落率はテーマ全体の地合いに近い
- N 小 (20-30以下) → 1〜2銘柄の急騰/急落で騰落率が大きく振れやすい
- 「構成[N]」「[94]→[65]」のように単独で引用したり推察の根拠にしたりしない

**2-2. ランク変動 × 騰落率 の組合せ読み**:
下落=悪材料、上昇=好材料という単純化はしない。

| 騰落率 | ランク変動 | 解釈 |
|---|---|---|
| 下落 | ↑ | テーマ自体への注目モメンタム加速 (当日は下げたが急上昇ランキングでさらに順位を伸ばす) |
| 上昇 | ↓ | ピーク打ち or 他テーマがより伸びた (当日は上げたがモメンタム鈍化) |
| 下落 | ↓ | テーマ離れ (注目モメンタムも衰える) |
| 上昇 | ↑ | 明確な追い風材料 (株価もモメンタムも揃って加速) |
| 上昇 | NEW | 新材料発生のシグナル。ニュース起点を最優先で特定 |
| 下落 | NEW | 先回り買い・思惑買いなど騰落率に表れにくい構造シフトの可能性 |

**2-3. market_data.html のデータ仕様**:
- **生成**: `make_market_db.py` を 18:00 以降に手動実行 (=当日生成)
- **基準時点**: 株探テーマランクは土日祝も数時間ごと更新されるため、騰落率・ランク変動は「直前更新時点のスナップショット」
- **整合性チェック**: テーマ騰落率と日経当日比に乖離 (例: 日経+1%でテーマ-1%) があれば、まず「セクターローテーション」、次に「別時点スナップショット」を疑う。両論併記してよい
- **土日祝**: market_data.html の日付をそのまま当日扱い。整合性チェックの比較先は **直前営業日の日経・TOPIX終値、当日のADR/夜間先物** (ADR等が拾えなければ夜間先物・週間レビューで代替可)

### 3. 市場全体の重要ニュース調査（マクロ）

テーマ別調査の**前に**市場全体を動かしうるマクロ材料を押さえる。各テーマの相対評価の基準になる。

カレンダー (手順1-3) に登録済みの「今後14日以内」イベントは、検索前に「あと N 日後に控える既知イベント」としてリストアップし、追加情報・最新の市場予想を M1〜M6 のいずれかに振り分けて検索する。

以下のカテゴリを**最低1回ずつ**検索:

- **M1. 国内政治・政策**: 政権・首相・大臣の動き、大型政策パッケージ、補正予算
- **M2. 米国マクロ**: 大統領発言、関税、FOMC・利下げ、米財政
- **M3. 地政学**: 戦争開始/停戦、領土紛争、サイバー攻撃などリスクオン/オフ転換点
- **M4. グローバル決算**: 米巨大ハイテク (AI/半導体/クラウド) の決算・ガイダンス
- **M5. 為替・金利**: ドル円、日銀政策、長期金利、原油・金
- **M6. 国内市況**: 直前営業日の日経・TOPIX終値、業種別騰落、ADR・夜間先物 (取得元は market_data.html ではなく WebSearch。ADR等が拾えない場合は夜間先物・週間レビュー等で補完可)

検索結果から、**継続中の大型材料**・**直近の転換点**・**地合いの分類** (リスクオン/オフ/一極集中) を整理。手順5の推察で個別テーマと突き合わせる比較対象になる。

### 4. テーマ別ニュース検索（アクター網羅）

各テーマで**アクターA〜D を最低1回ずつ**検索 (1テーマあたり3〜4回想定)。アクターE (相場) は手順3を流用、追加検索不要。

**4-1. 類語展開**:
検索前にテーマ名の類語を2〜3個挙げる。テーマ名そのままだと公的文書・正式名称にヒットしないことが多い。

- カタカナ↔漢字の公式用語
- 略語↔正式名称
- 業界用語↔一般語
- 周辺技術・上位/下位概念

思いつかなければ `"{テーマ名}" 関連銘柄 別名 OR 正式名称` で1回引き出す。

**4-2. アクター別検索**:
クエリは **テーマ名 or 類語 + アクター語彙 + シグナル語彙 + 現在の年月**。

- **A. 政治**: 大臣/首相/与党 + 表明/発言。担当大臣はテーマから管轄省庁を推論 (防衛/経産/デジタル/金融/厚労/国交/文科/環境/農水)。現職氏名はハードコードせず検索結果から拾う。**閣議決定より早く株価に効く**
- **B. 行政**: 政府/省庁/閣議決定/審議会/検討会。狙いは行動計画・補正予算・規制改正
- **C. 海外**: 米国/中国/EU/関税/輸出規制。同業国の政策、対立構造、サプライチェーン影響
- **D. 企業**: 決算/業績修正/提携/受注。代表銘柄の個別材料。**特にランク↑N / NEW で急浮上したテーマでは、代表銘柄(リーダー株)の前日〜当日の相場状況 (急騰・出来高急増・年初来高値・S高近辺) を1回検索し、起点となった個別材料を逆引きする**。テーマ全体のニュースより個別銘柄の動意が起点のケースは多い

期間は **今日 → 直近1週間 → 直近1ヶ月** の順で、十分な材料が見つかれば打ち切り。

A〜D のいずれかで「介入」「数値コミット」「国際連動」シグナルにヒットしたら**最優先で採用**。

**4-3. 日付検証**: 個別株の値動き (+N%, S高, 年初来高値等) を本日材料として引用する前に、**記事日付が今日 or 前営業日かを必ず確認**。WebSearch は過去の同銘柄ニュースをトップに返すことがあり、古い急騰を当日材料と取り違える事故が起きる (例: 5/20調査でGSユアサ「+5.62% 17年ぶり高値」を引用したが実態は2月の記事・本日は-3%)。日付不明なら引用しない。

**4-4. 年省略日付の年特定**: 「6月5日」のように年省略の日付を引用する前に、年を必ず特定する。「今年」と暗黙に補完しない。確定できなければ引用しないか「YYYY年M月D日」と年付き明示。

事故例: 5/25 調査で「6月5日新規上場」(=2024年実績) を 2026 年と勝手に補完し「6/5 アストロスケール上場接近・あと11日」と誤記。

### 5. 推察

各テーマで以下を統合:

- 個別材料（手順4のA〜D）
- マクロ材料（手順3のM1〜M6）
- 過去履歴（手順1-1）の継続性・転換点
- 騰落率 × ランク変動の組合せ（手順2-2）

**5-1. 全体相場との比較**:

- 市場リスクオン下の下落 = 個別逆風 or 高値警戒利食い
- 市場リスクオフ下の上昇 = **明確な相対強さ**
- 一極集中相場 → 蚊帳の外テーマは絶対値下落でもランクキープなら相対強さ

**5-2. カレンダーイベントとの距離**:
今後14日以内に登録済みイベントがあれば、各テーマの当日のランク変動・騰落率がそのイベントへの「先回り / 様子見 / 織込み済」のどれに該当するかを1文で明示。

**5-3. 釣り合いチェック**:
材料の大きさとランク変動が釣り合うかを自問。釣り合わなければ隠れ材料の可能性、追加検索する。推察は「〜と考えられる」「〜の可能性」で推測明示。

### 6. 出力

`{今日の日付}` は手順 1-0 で確定した価格日 (YYYY-MM-DD)。

```
## テーマ急上昇ニュース（{今日の日付}）

### 市場全体サマリー
- **地合い**: {分類 + 直前営業日の日経・TOPIX終値}
- **重要マクロ材料**: {継続材料・転換点を2-4件}
- **テーマ評価の前提**: {全体相場下での上位3テーマの位置付け1-2文}

### 1. {テーマ名}（騰落率: {騰落率}、ランク変動: {↑N/↓N/→/NEW}）

**主な材料・ニュース**
- {要約1}（アクター: 政治/行政/海外/企業）⟨1⟩
- {要約2} ⟨2⟩⟨3⟩

**推察**
{材料×ランク変動×地合いで2-3文}

**Sources**
- [1] [記事タイトル](URL)
- [2] [記事タイトル](URL)

### 2. ...
### 3. ...
```

**6-0. インライン脚注 `⟨N⟩` の付与**:

本文の主要な事実に末尾 `⟨N⟩` (mathematical angle bracket、U+27E8/U+27E9) を付ける。`/market` 表示時にクリックすると Sources の該当行へジャンプする。

- **記号は `[]` ではなく `⟨⟩`**。`[N]` は構成銘柄数 `[99]` と衝突するため必ず `⟨⟩` を使う
- 対象: 要人発言・決算/業績修正の数値・個別株値動き (+N%, S高等)・政策の固有金額・海外指標 (FOMC/関税/原油/為替)
- 推察文には付けない (= AI 解釈であって記事引用ではない)。例外: 推察内で記事の主張を直接引用するとき
- 番号は本文初出順 (1 から開始、テーマをまたぐ通し番号)
- 同じ記事を 2 度引く場合は同じ番号を再利用
- 1 主張あたり最大 3 つ (`⟨1⟩⟨2⟩⟨3⟩` まで)。4 つ以上は最も説明力のある 3 つに絞る
- 隣接表記は `⟨1⟩⟨2⟩` (個別、Wikipedia 方式)

出力例:
```
- C海外+E相場: 米イラン停戦合意期待で AI 半導体一極相場復権 ⟨1⟩⟨2⟩、太陽誘電 (6976) ストップ高 ⟨4⟩
```

**6-1. Sources に並べる基準**:

「本文の材料・推察を裏付ける**重要な参照**」だけを Sources に並べる。本文に登場する固有名詞を機械的にリンク化しない。

**並べ方**:
- 番号は本文の脚注 `⟨N⟩` 初出順 (テーマをまたぐ通し番号)
- 行頭フォーマット: `- [N] [タイトル](URL)` (`[N]` は半角ブラケット、これは webapp 側で `<li id="thn-src-N">` に変換され anchor target になる)
- 本文に `⟨N⟩` で参照されない記事は Sources にも載せない (本文 ⟨N⟩ ↔ Sources [N] の双方向対応を保証)


◯ 並べる:
- 当日 or 直前営業日の固有イベントを伝えるニュース記事 (政策発表・決算リリース・報道・要人発言)
- 本文の論旨を補強する説明力のある過去記事 (政策ロードマップ・歴史的経緯・テーマ背景など、説明力があれば過去のものでも可)

× 並べない:
- 市況スナップショット数値の参照ページ — 終値・金利・為替・指数値などは分析の前提データで、論旨を裏付ける「主張ソース」ではない
  - × 「[フジプレアム5/21終値343円・5/15決算純損失23億円拡大](https://finance.yahoo.co.jp/quote/4237.T)」
  - × 「[日本10年金利5/21 2.775%](https://www.nikkei.com/topics/...)」
- 個別銘柄ページのトップ URL (`finance.yahoo.co.jp/quote/XXXX.T` 等) — 動的に変わるので証拠価値なし
- 本文に出てきた固有名詞 (銘柄名・人名・組織名) の単なるリファレンス
- 社内データ事象 (テーマランク順位変動など) — 出典は社内 DB、URL を貼らず本文で完結させる

「Sources を見れば本文のどの主張がどう裏付けられるか分かる」状態を目指す。リンクが本文の主張に紐付かないなら削除する。

### 7. 履歴保存

`.claude/skills/theme-news/history/{今日}.md` (= 手順 1-0 の価格日) に要約を Write。ディレクトリ無ければ `mkdir -p`、同日再実行は上書き、本文は1行圧縮 (材料・推察)。**Sources セクションは手順 6 で並べた URL リストをそのまま含める** (webapp の `/market` 表示で出典確認に使う)。

**⚠️ ファイル名は手順 1-0 の Bash で取得した価格日をそのまま使う**:
- 17:00 前に実行された場合、`date.today()` (実カレンダー日) と価格日は **1日ずれる**
- 例: 5/21 16:30 実行 → 価格日 = `2026-05-20` → ファイル名は **`2026-05-20.md`**
- `date.today()` / カレンダー日付・現在日時から推論した日を使うのは**禁止**。必ず 1-0 の Bash 出力を参照
- run_theme_news.py ラッパー側でファイル名と価格日の一致を検証しており、ズレた場合は失敗扱いとなる

本文中の「{今日の日付}」(見出し行) も同じ価格日を使う。

```
# テーマ急上昇ニュース要約（{今日の日付}）

## 市場全体
- 地合い: {1行}
- 重要マクロ材料: {1-2行}

## 1. {テーマ名} ({騰落率}, {ランク変動: ↑N/↓N/→/NEW})
- 材料: {最重要材料1行・アクター種別含む} ⟨1⟩
- 推察: {結論1行・市場全体との相対位置に触れる}

## 2. ...
## 3. ...

## Sources
- [1] [記事タイトル](URL)
- [2] [記事タイトル](URL)
- ...
```

Sources は手順 6-1 の基準を満たす URL のみ。本文の主張を裏付けないリンク・市況スナップショット URL は載せない。Sources を省略すると `/market` 側で details 折りたたみが消え、出典追跡ができなくなる。

本文中の脚注は `⟨N⟩` (mathematical angle bracket)、Sources 行頭は `[N]` (半角ブラケット) で使い分ける。構成銘柄数 `[99]` の表記は据置 (脚注記号 `⟨⟩` と衝突しない)。

### 8. 株カレンダー更新

`events.json` を編集 → `python .claude/skills/theme-news/render_calendar.py` で `calendar.html` を再生成。`calendar.html` は直接編集しない (上書きされる)。

**8-1. 拾う基準**:
当日の調査本文 (手順6) から、以下をすべて満たすイベントだけを拾う。

- **実際の相場・市場・世相に関する出来事** (マクロ/政治/企業/個別株動意)。**システム内部のテーマランク変動・順位定着・急浮上などはカレンダー対象外** (テーマニュース調査本文側で扱う)
- 日付が特定可能 (M/D, M/D-D, M月のいずれか)
- アクターA/B/C/D 発の固有イベント
  - ◯: 「5/20 NVIDIA決算」「6月日銀会合」「5/13-15 Trump訪中」「7月参院選」「5/20 自衛隊基地ペロブ導入実証報」
  - ×: 「3日続落」「日経-1,244円」「10年金利2.73%」(= 単発の市況数値、日付が事象を指していない)
  - ×: 「ペロブ #3↑20 急浮上」「蓄電池 #1↑3」「順位定着」(= テーマランク変動はシステム内事象、カレンダー対象外)
- 関連テーマが当日トップ3 or 過去30日履歴のテーマと紐付く

**8-2. events.json への追記**:
ファイル先頭の既存エントリをスキーマ見本として参照し、日付昇順で追加する。フィールドは `id` / `title` / `start` / `end` / `importance` / `themes` / `body` の7つ。日付未確定なら `tentative: true` と `tentativeNote` を追加し、`start`/`end` には対象月の1日 or 直近営業日を入れる (グリッドは点線・?マークで自動表示)。

重要度の基準 (迷ったら**低めに振る**):

| importance | 基準 |
|---|---|
| `"high"` | 政治/海外/巨大企業発、複数上位テーマ直結、日経±500円級想定 |
| `"mid"`  | 行政/単一テーマ主役級、週次インパクト |
| `"low"`  | 参考レベル |

**8-3. 更新・アーカイブ**:
- 既存エントリと `title` 類似 or 日付±3日以内 → 新規追加せず、既存オブジェクトを書き換え (`id` は維持)
- `end < TODAY` になったエントリは `body` 末尾に「→ 実績: ...」を追記。それ以外の処理は不要 (グリッドが自動で淡色化)
- `end < TODAY - 30 日` のエントリは events.json から削除し、`calendar-archive.html` 末尾の `<tbody>` に `<tr>` として追記 (アーカイブ日列に今日の日付)

**8-4. HTML 再生成**:
```bash
python .claude/skills/theme-news/render_calendar.py
```
メタ日付 (`last-updated` / `today`) と `<script id="events-data">` が `ks_util.get_price_day()` ベースで自動更新される。
