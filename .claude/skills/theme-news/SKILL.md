# テーマ急上昇ニュース調査

market_data.html のテーマランク上位3テーマについて、急上昇・急下降の理由となる市場ニュース・材料をWebSearchで調査し、株式市場動向を踏まえて推察する。調査結果はデイリーでマークダウン保存し、直近1ヶ月分を次回以降のコンテキストに活用する。

## 手順

### 1. 過去の調査履歴を読み込み（コンテキスト用）

`.claude/skills/theme-news/history/` 配下の**直近1ヶ月分**（今日を含む過去30日以内）の要約マークダウンファイルを読む。

- `Glob` で `.claude/skills/theme-news/history/*.md` を取得
- ファイル名は `YYYY-MM-DD.md` 形式。今日の日付から30日前以降のものだけ `Read` で読み込む
- ファイルが存在しなければスキップ（初回実行を想定）
- 各ファイルは要約形式（テーマ名・騰落率・材料1行要約・推察1行要約のみ）なので、30日分まとめて読んでもコンテキスト肥大の心配は少ない
- 読み込んだ内容は、テーマの継続性（連日ランクインしているか、騰落率の推移、同じ材料が尾を引いているかなど）の推察に使う

### 2. テーマランクデータの読み取り

`$KS_DATA_DIR/code_rank_data/market_data.html`（デフォルト: `/Users/k_sohara/Ext/GoogleDrive/shintakane_data/code_rank_data/market_data.html`）を読み込み、以下を抽出する:

- `<h2>テーマランク</h2>` の後にある `<div class="theme-grid">` 内の `<div class="theme-badge ...">` 要素を解析する
- 各バッジから以下を取得:
  - ランク: `<span class="rank">` の内容（例: `#1`）
  - テーマ名: `<span class="name">` の内容
  - 騰落率: `<span class="rate ...">` の内容（例: `+0.1% [95]`）
- 上位3テーマ（#1〜#3）を取得する

### 3. 各テーマのニュース検索（今日重視、期間優先順）

上位3テーマそれぞれについて、以下の優先順でWebSearchを実行する。**1テーマあたり複数回の検索を許容**する。

1. **今日のニュース（最優先）**: `"{テーマ名}" 株式 材料 {今日の日付: YYYY年MM月DD日}`
2. **直近1週間**: 今日のヒットが乏しければ `"{テーマ名}" 株 急騰 OR 急落 {現在の年月}`
3. **直近1ヶ月**: さらに補足が必要なら `"{テーマ名}" テーマ株 材料 {現在の年月}`

検索は日本語で。速報性のある市場ニュース・材料に絞る。今日付けの材料が見つかった時点で次のクエリは省略してよい。逆に今日の材料が薄い場合は、直近1週間→1ヶ月の材料で背景を補う。

### 4. 株式市場動向を踏まえた推察

各テーマについて、以下を踏まえて**なぜ上昇/下降しているか**を推察する:

- 個別材料（決算、業績予想修正、新製品、政策、提携、受注など）
- セクター全体のトレンド（AI投資、金利動向、為替、地政学リスクなど）
- 過去履歴（手順1で読んだ）から見える継続性・転換点
- 騰落率の符号と大きさ（大きなプラスなら材料追い風、マイナスなら他要因での調整か）

推察は断定せず「〜と考えられる」「〜が背景にある可能性」など推測であることを明示する。

### 5. 結果の出力

以下のフォーマットで回答する:

```
## テーマ急上昇ニュース（{今日の日付}）

### 1. {テーマ名}（騰落率: {騰落率データ or "データなし"}）

**主な材料・ニュース**
- {ニュース要約1}
- {ニュース要約2}

**推察**
{なぜこの騰落率なのか、市場動向と絡めた推察を2-3文}

**Sources**
- [記事タイトル1](URL1)
- [記事タイトル2](URL2)

### 2. {テーマ名}（騰落率: ...）
...

### 3. {テーマ名}（騰落率: ...）
...
```

過去履歴から継続性が見える場合は、推察セクションで「{N日前}からランクイン継続」「騰落率は{日付}の+X%から縮小」など軽く触れる。

### 6. 調査結果の保存（要約版）

`.claude/skills/theme-news/history/{今日の日付:YYYY-MM-DD}.md` に**要約版**を `Write` で保存する。回答本文そのものではなく、後続実行時のコンテキスト用に絞り込んだ形式にする（30日分まとめて読んでも肥大化しないよう、1日あたり10〜20行程度に収める）。

- ディレクトリが存在しない場合は `Bash` で `mkdir -p` してから書き込む
- 同日に再実行した場合は上書きしてよい
- Sources（URL一覧）は保存しない（回答時のみ出力。過去URLは次回の推察に不要）
- ニュース要約は各テーマ1行に圧縮（最重要の材料1点のみ）
- 推察も1行に圧縮（結論のみ）

保存フォーマット:

```
# テーマ急上昇ニュース要約（{今日の日付}）

## 1. {テーマ名} ({騰落率})
- 材料: {最重要材料を1行で}
- 推察: {上昇/下降理由の結論を1行で}

## 2. {テーマ名} ({騰落率})
- 材料: ...
- 推察: ...

## 3. {テーマ名} ({騰落率})
- 材料: ...
- 推察: ...
```

## 注意事項

- 各テーマにつき2-3件のニュース・材料を簡潔に要約する
- 出典URLを必ず付記する（Sourcesセクション）
- HTMLファイルが存在しない、またはテーマランクセクションがない場合はその旨を伝える（保存はスキップ）
- 検索結果が見つからない場合は「関連ニュースが見つかりませんでした」と記載し、推察は市場全体の動向から行う
- 過去履歴の読み込みに失敗してもエラーとせず、新規調査として進める
