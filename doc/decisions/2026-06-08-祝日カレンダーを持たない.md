# 営業日判定に祝日カレンダーを持たない

- Status: Accepted
- Date: 2026-06-08
- Related: アーキテクチャ.md §4

## Context

日次データの取得や経過日数の計算で、営業日の判定が要る。祝日も休場日として扱うかを決める必要があった。

## Decision

営業日は `get_price_day()` (17時前は前日扱い) と `recent_weekday()` (土日なら直近の金曜に丸める) だけで判定する。祝日カレンダー (`jpholiday` 等) は導入しない。

## Rationale

- 価格・RS・MA は yfinance の営業日 index に乗るので、祝日は元から含まれない
- 祝日を平日扱いする実害は、祝日に日次データを余分に取りに行く軽い HTTP (年に数十回) だけで、データは壊れない
- これを消すために依存を足すのは過剰 (Simplicity First)

## Consequences

再検討のきっかけ:

1. 取得コストが課金や rate limit に当たるようになった
2. 日付指定での営業日数の演算が要る機能ができた (今は配列のインデックスで代用している)
3. 休場日の「未更新」誤警告が運用のノイズになった

導入するときは `ks_util.py` に祝日対応版の営業日ヘルパーを足し、`recent_weekday()` の利用箇所を置き換える。
