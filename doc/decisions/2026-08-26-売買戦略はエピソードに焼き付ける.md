# 売買戦略はエピソードに焼き付ける (銘柄の現在の戦略を参照しない)

- Status: Accepted
- Date: 2026-08-26
- Related: #419, #437, #424

## Context

売買履歴の目的は「売買戦略ごとに成績を集計し、今後の戦略の参考にする」こと。
しかし戦略 (`trade_idea`) はポートフォリオの銘柄レコードにしか無く、エピソードと結びついていなかった。

## Decision

- 戦略は `episode_strategy:<episode_key>` として **エピソードごとにコピーして保存する**。銘柄の `trade_idea` を参照しない
- 値はマスター登録済みの戦略名だけを許す
- 埋め方は3層: 初回一括シード (保有日数が戦略の `time_horizon` と矛盾するものはシードしない) → 銘柄単位の一括付与 → 個別上書き
- シードした値は `source="seed"`、人が確認した値は `source="manual"` で区別する

## Rationale

- `trade_idea` は「現在の戦略」1個しか持てない。同じ銘柄に別戦略で入り直すと上書きされ、過去エピソードの戦略が壊れる。参照では集計できない
- **高回転銘柄への一括付与は採用しない**。例: 6227 に「中長期ファンダ」を14件シードすると、中長期ファンダの平均保有日数が5日になり、戦略の定義が崩れる
- **保有日数から戦略を自動推定しない**。戦略は「入るときの意図」であって結果の保有期間ではない。中期モメンタムで入って3日で損切りしたものを「短期」にすると、知りたい答えが歪む
- 往復行 (#424) 単位のキーに従属させない。往復行は集計の母数になれず、戦略混在の問題も一部にしか効かない

## Consequences

- `episode_key` (`code_s|kind|first_seq`) の安定性に依存する
- 保有中に素通しでシードした分は、クローズ時に足切りを再評価する
- `trade_idea` 自体の変更履歴は持たない
