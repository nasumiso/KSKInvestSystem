# 売買戦略はエピソードに焼き付ける (銘柄の現在の戦略を参照しない)

- Status: Accepted
- Date: 2026-08-26
- Related: #419, #437, #424

## Context

売買履歴の目的は「売買戦略ごとに成績を集計し、今後の戦略の参考にする」こと。
しかし戦略 (`trade_idea`) はポートフォリオの銘柄レコードにしか無く、エピソードと結びついていなかった。

## Decision

- 戦略は `episode_strategy:<episode_key>` として **エピソードごとにコピーして保存する**。銘柄の `trade_idea` を参照しない
- 値はマスター登録済みの戦略名だけを許す
- 埋め方は3層: 初回一括シード (保有日数が戦略の `time_horizon` と矛盾するものはシードしない) → 銘柄単位の一括付与 → 個別上書き
- シードした値は `source="seed"`、人が確認した値は `source="manual"` で区別する

## Rationale

- `trade_idea` は「現在の戦略」1個しか持てない。同じ銘柄に別戦略で入り直すと上書きされ、過去エピソードの戦略が壊れる。参照では集計できない
- **高回転銘柄への一括付与は採用しない**。例: 6227 に「中長期ファンダ」を14件シードすると、中長期ファンダの平均保有日数が5日になり、戦略の定義が崩れる
- **保有日数から戦略を自動推定しない**。戦略は「入るときの意図」であって結果の保有期間ではない。中期モメンタムで入って3日で損切りしたものを「短期」にすると、知りたい答えが歪む
- 往復行 (#424) 単位のキーに従属させない。往復行は集計の母数になれず、戦略混在の問題も一部にしか効かない

## Consequences

- `episode_key` (`code_s|kind|first_seq`) の安定性に依存する
- 保有中に素通しでシードした分は、クローズ時に足切りを再評価する
- `trade_idea` 自体の変更履歴は持たない → 2026-09-30 に改めた (下記)

## 追記 (2026-09-30, #492 段階1)

- 銘柄・エピソードの戦略の変更を、有効日つきの変更履歴 (`strategy_history:<code_s>`) に残す。記録開始時に全銘柄の今の戦略を基準値として残す
- 記録開始日以降に建てたエピソードには、建てた日に有効だった銘柄の戦略を履歴から引いて `source=entry` で付ける (銘柄の現在の戦略は参照しない、という本決定の考えはそのまま。値を引く時点を「建てた日」に固定する)
- 時間軸と保有日数の矛盾で外すのは `seed` だけ。入った時点の意図 (`entry`・`manual`) は、早く切っても外さない
- 保有中に銘柄の戦略を付け替えても (例: GARP で入り、防衛線を割った後に中長期ファンダへ)、エピソードの戦略は変えない。変えると入った時点の戦略の成績から負けが消える。付け替えの跡は変更履歴に、その瞬間の出口ルールと防衛線の状態つきで残す

## 追記 (2026-10-05, #492 段階2)

- エピソードの戦略は、建てロットの戦略の**初期値**とする。建て側の fill に別の戦略を付けたロットだけが、エピソードと違う戦略で数えられる (`fill_strategy:<code_s>|<seq>`)。1つのエピソードに意図の違う玉が同居する例 (285A・4258: 中核の玉と、戻りで売るつもりの押し目買い) を分けるため
- 戦略別の成績は、クローズ済みエピソードの決済済みの往復行を、建てロットの戦略で集計する。当初「往復行は集計の母数にしない」とした根拠は、往復行の損益合計がエピソード損益と 35.6% ずれていたこと (2026-08-31)。2026-10-05 に運用機で測り直すと、クローズ済み 390 エピソードで不一致は 0 件だった。この一致を不変条件にして、母数を往復行に変えた
- 上書きの無いエピソードは、戦略別の損益合計が変わらない。件数・勝率・平均保有日数は往復行単位になる
- 往復行にはキーを付けない。戦略は買いに付くので、遡り取込で FIFO の組が変わっても意図は別の取引に移らず、変わるのは損益の振り分けだけ
- 保有中エピソードの決済済みロットは、引き続き比較に入れない (保有中の現物は、往復行の FIFO と実現損益の平均取得単価法が一致しない)
- 防衛線はロットごとには当てない (未決)。保有銘柄一覧は銘柄の戦略、エピソードチャートはエピソードの戦略で引く
