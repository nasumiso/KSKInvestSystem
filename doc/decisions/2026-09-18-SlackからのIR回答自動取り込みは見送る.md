# Slack からの IR問い合わせ回答の自動取り込みは見送る

- Status: Accepted
- Date: 2026-09-18
- Related: #436 (IR問い合わせ回答 `ir_qa`)

## Context

IR部門への問い合わせ回答が、ユーザーの参加する Slack チャンネルに投稿される。これを WebApp の `ir_qa` (#436) へ自動で登録できないかを検討した。

前提として、Claude Code は Slack と連携していない。Claude in Slack は Anthropic のサーバーで動くため、ローカルの WebApp/DB には触れない。ユーザーはワークスペースの一般参加者で、管理者への依頼は難しい。

## Decision

自動取り込みは行わず、#436 のフォームへの手動コピペ (実測1分程度) を続ける。

銘柄と回答日の判断が要る部分はユーザーが決め、分割・整形・登録を Claude に頼む分担はできる (例: 「マルマエ 6264、4月分は 2026/04/01、8月分は 2026/08/XX で登録して」)。新しい実装は要らず、`POST /stock/<code>/ir_qa` をそのまま使う。

## Rationale

取り込む経路は作れる。ただし、Slack メッセージから「どの銘柄の、いつの回答か」を機械的に判定できない。実サンプル2件 (マルマエ / サムコ) では、次の4点すべてで人の判断が必要だった。

1. 本文に社名だけがあり、銘柄コードが無い。IR回答は再取得できない情報なので、社名からの推定による誤登録は実害になる
2. 1メッセージに複数の回答日が混ざっている (「2026年4月当初」と「2026年8月」が1投稿内)。`ir_qa` は1エントリ=1回答日
3. 見出しに日が無く、`answered_at` (YYYY/MM/DD) を確定できない
4. 投稿日と回答日が違う (4月の回答を8月に転記)。Slack の `ts` は使えない

このため自動で運べるのは inbox までで、その先はすべて手作業になる。Slack から直接コピペするのと手間が変わらず、inbox の管理コストだけが増える。

採用しなかった経路:

| 方式 | 判断 |
|---|---|
| Bot Token + Slack MCP / cron | App 作成・スコープ付与に管理者権限が要る |
| User Token | 他人のワークスペースにアプリを入れるのは筋が悪い |
| Playwright で Slack Web を読む | DOM 変更の保守コストと規約リスク |
| WebApp を ngrok 等で公開して Make から叩く | 認証が無いので不可 |
| Make (インストール済み) → Google Drive の inbox → ローカルで登録 | 技術的には成立する (無料枠で足り、公開エンドポイントも不要)。上記4点の判定問題で見送り |

## Consequences

- 取り込み用の実装・保守は発生しない。登録の正確さ (銘柄と回答日) は人が保証する
- 次のどれかが満たされたら見直す:
  - IR回答が週に数件以上流れてくるようになった (現状は不定期で月1〜2件程度)
  - 投稿フォーマットが安定した (銘柄コード併記・1投稿1回答日・日付が YYYY/MM/DD)
  - 管理者に読み取り専用の Bot Token (`channels:history` または `groups:history` + Bot 招待) を相談できるようになった
- 見直す場合は、Make + Google Drive 中継の構成が第一候補になる
