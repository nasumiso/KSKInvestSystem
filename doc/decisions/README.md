# 設計判断記録

このフォルダには、将来も「なぜこの設計を選んだか」を参照する価値がある判断だけを残します。
実装手順、調査ログ、完了済みissueの詳細な経緯は Git / Issue / PR の履歴に残るため、ここへ複製しません。

## 記録する判断

- 複数案から選び、後から見直す可能性がある設計
- データ互換性、外部公開、権限、運用方法に関わる方針
- 「なぜ採用しなかったか」を残さないと、同じ検討を繰り返しそうな判断

単なる実装詳細、短期的なTODO、コードから自明な内容は記録しません。

## ファイル形式

ファイル名は `YYYY-MM-DD-短い題名.md` とします。1判断を1ファイルにします。

```md
# <判断の題名>

- Status: Accepted / Superseded
- Date: YYYY-MM-DD
- Related: #issue または関連ドキュメント

## Context

何を解決する必要があったか。

## Decision

採用した方針。

## Rationale

選定理由と、採用しなかった主要な案。

## Consequences

得られる利点、受け入れる制約、将来の見直し条件。
```

既存の計画書を整理する際は、現行仕様に必要な内容を `ARCHITECTURE.md`、`COMMANDS.md`、`MCP.md` 等へ反映し、この形式で残す価値がある判断だけをここへ切り出します。残りの計画書は削除しても Git 履歴から参照できます。
