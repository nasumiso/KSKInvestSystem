# ポートフォリオCSVを保有数量・保有ステータスの真実源にする

- Status: Accepted
- Date: 2026-08-10 (2026-09-15 に保留キュー廃止と 3監 の自動IN を反映)
- Related: #397, #363, #444

## Context

保有株数 (`qty`) と保有ステータス (1保/2準/3監) を手入力で管理していたため、実際の残高とずれていた。
一方で #363 により「非1保 → 1保 の遷移には売買戦略 (`trade_idea`) の宣言が必須」という規律がある。
CSV で機械的に 1保 にすると、この宣言が飛ぶ。

## Decision

- 証券会社の残高CSV (楽天・SBI の現物/信用 4ソース合算) を **`qty` と `status` の真実源**とする。「人が管理し機械が検算する」ではなく「機械が同期し、人は理由を書く」
- CSV が上書きするのは事実 (`qty` / `status`) だけ。**判断・理由 (`memo.trade_idea`, `memo.*`, action_log) は上書きしない**。action_log は追記のみで、取込による変更は `source="csv_import"` の新しいログとして積む
- 全ソースが揃った銘柄 (covered) だけを更新する。ソースが欠けた銘柄は判定不能として触らない
- OUT (残高0) は無条件で 2準 に落とす。IN は **2準 または 3監 で、戦略が設定済み** のときに自動。戦略が無いときは取込プレビュー画面で戦略を選んで確定する (空欄なら変更しない)
- 取込は週次・手動。cron 化しない

## Rationale

採用しなかった案:

- **戦略を「未分類」で自動IN** — #363 の目的 (出口ルール未宣言のポジションを作らない) を無効化する
- **直近の action_log から戦略を推測** — 過去の戦略と今回のINが同じ保証がない。誤った出口ルールが付く方が無宣言より悪い
- **取込時に対話的に戦略を聞く CLI** — WebApp からの取込に統一できない
- **3監 は自動INしない** (当初案) — 3監 の `trade_idea` は過去の保有の名残の可能性がある、として当初は除外した。しかし実運用で 3監 からの買い直しが起き、戦略があっても永久に自動INされなかったため、#444 で 2準 と同じ扱いに改めた
- **保留キュー (pending_in) で戦略入力を待つ** — 当初は採用したが、キューを消化するUIが無く、取込プレビューで戦略を選べるようになった時点で存在意義が消えたため 2026-09-15 に廃止 (#444)
- **cron 化** — 4ファイルの手動ダウンロードが必要で自動化できない

## Consequences

- 手入力の `qty` / `status` は次回取込で上書きされる前提になる
- 売却日は取込日基準でずれるが許容する。損益・振り返りは fill 側 (売買履歴タブ) で行う。action_log 側の売却後騰落率 (`post_sell_returns`) は廃止した
- 売建は検出して警告するだけで、自動更新の対象外
- `portfolio_shelve` の pending_in API は、戻せるように残してある (呼び出し元なし)
