# テーマ別ブレイクは株探テーマの本日リストを数える

- Status: Accepted
- Date: 2026-10-25
- Related: #509, [2026-05-29 の判断](2026-05-29-業態テーマのローテーション検知は既存指標の集約で作る.md)

## Context

日次発掘レポート (`shintakane_result.csv`) は1日 270〜540 行あり、テーマで並んでいないので見られていなかった。2026-09-15〜10-09 のセキュリティでは、既に調べた銘柄 (1保・2準・3監) がまとまって新高値を付けていたが、どこにも出ていなかった。

2026-05-29 の判断は、業態テーマ (手動分類) で RSライン新高値をグループ集計する案を「独自の breadth 指標になる」として採らなかった。今回の集計はそれと性質が近い。

## Decision

- /market に「テーマ別のブレイク」を出す。日次バッチが既に作っている本日リスト (新高値・出来高急増・PTS) の銘柄を、CSV の「テーマ」列 (株探テーマのうち主要3つ) で数える
- 出すのは、5銘柄以上かつ前20営業日の平均の 2.5 倍以上のテーマ。構成銘柄の 6 割以上が先の行と重なるテーマは別名として畳み、8 行まで
- 構成銘柄は管理対象 (1保 → 2準 → 3監) を先に出す。未フォロー銘柄は、該当テーマ内で本日初めて載った新高値を、業績スコア順に 1 テーマ 2 銘柄まで
- 未フォロー銘柄を監視に入れると、action_log の reason に `発掘元:日次レポート テーマ=… 日付=…` を残し、月次の振り返り (`trade_review` の `discovery`) で拾う
- 集計はリクエストごとに CSV から作り、ファイルや DB に書かない

## Rationale

- 2026-05-29 との違い: こちらは市場の自動分類 (株探テーマ) で、既に出ている本日リストの銘柄数を数えるだけ。新しい指標の計算も、過去時点の再計算も要らない。スコア・ランキング・評価台帳には入れない
- 主要3テーマで数えるのは、過去の CSV にそれしか無く、過去分と当日分の数え方を揃えるため
- 未フォロー銘柄を業績スコア 70 以上で絞る案は採らなかった。1日平均 1.3 銘柄で、該当なしの日が6割を超え、レポート発の取引の成績を比べる件数が集まらない。初出の条件では選べないこと ([#509 の調査](https://github.com/nasumiso/KSKInvestSystem/issues/509#issuecomment-6107641546)) は確かめてあり、表示は候補を増やすためではなく、効き目を測るための入口として最小限にした
- 出来高急増だけ・PTS だけ・材料で大きく跳ねた未フォロー銘柄は出さない。調査でいちばん負けた場所のため
- バッチで JSON に出す案は採らなかった。21日分の CSV の読み込みは約 40ms で、新しいファイルを足さず、バッチの順序 (CSV は market_data.html より後に書かれる) にも依存しない

## Consequences

- 2026 年の 165 営業日で、1日平均 3.1 行、該当なしは 19 日、8 行を超えたのは 3 日。未フォロー銘柄は1日平均 3.4 銘柄
- 主要3テーマはその日のテーマランク順で選ばれるので、ランク外のテーマは数えにくい
- 「読売333」「親子上場」のような、テーマとは言いにくい分類も出ることがある
- **見直し条件**: 四半期末の仕様レビューで、使っていない、または既に調べた銘柄の動きに気づけた例が無ければ外す
