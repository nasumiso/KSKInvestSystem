# momentum_pt の対数正規分布モデル化と動的キャリブレーション 要件定義

> 既存の momentum_pt（モメンタムスコア、総合スコアの25%配分）の算出ロジックを、対数正規分布モデルに置き換え、相場環境に追従する動的キャリブレーション機構を導入する。
>
> 関連 issue: #104

---

## 1. 背景

### 現状の momentum_pt 計算

`scripts/price.py` の `calc_momentum_pt()` は、以下の流れで momentum_pt を算出している。

1. 銘柄の rs_raw（13/26/39/52週株価変化率の加重平均）を計算
2. TOPIX 対比の比率を計算: `rs_rel = rs_raw / topix_rs_raw`
3. rs_rel が「平均1.0、標準偏差0.3の正規分布」に従うと仮定し、CDFでパーセンタイル化
4. 結果を 0〜100 の整数値として momentum_pt に格納

scale=0.3 はコメントに「code_rank実測のrs_raw標準偏差」とあるが、初回コミット時点からハードコードされており、根拠がGit履歴に残っていない。

### 課題

#### 課題1: 正規分布の仮定が破綻している

実データ（3,822銘柄）で rs_rel の分布を検証した結果、正規分布から大きく乖離していることが判明した。

| 指標 | rs_rel（生値） | log(rs_rel) |
|------|---------------|-------------|
| 歪度 | **+8.13** | +0.37 |
| 超過尖度 | **+144.95** | +13.55 |
| 標準偏差σ | 0.3693 | 0.2750 |

rs_rel は比率指標であるため構造的に右に歪む（上方向は青天井、下方向は0で止まる）。これを生のまま正規分布で扱うのは数学的に無理がある。一方、対数変換すれば歪度が二桁改善し、ほぼ対称なベル型分布になる。

#### 課題2: scale パラメータが固定で相場環境に追従しない

scale=0.3 はハードコードされており、実測値（0.3693）と比較して+23%の乖離がある。

- 強気相場では rs_rel 分布が広がる（強銘柄と弱銘柄の差が大きくなる）
- 弱気相場では rs_rel 分布が狭くなる
- レンジ相場では中間的

固定 scale ではこれらの環境変化に追従できず、強気相場では中央寄りの偏ったスコアが出やすい（極端な値が出にくい）。

### 経験ランク方式が選択肢にならない理由

理論的には、分布仮定を置かない経験ランク方式（全銘柄をrs_rawでソートしてパーセンタイル化）が最も素直な解である。しかし、Shintakane のシステム設計上、これは採用できない。

- 全銘柄の rs_raw を毎日同時に更新する仕組みがない
- 日次更新対象はウォッチリスト + 新高値・出来高急増のトリガー検知銘柄のみ
- 「ある時点で全銘柄の rs_raw が揃っている」という前提が成立しない

したがって、**個別銘柄の momentum_pt は、その銘柄単独で独立に計算できる必要がある**。これは分布仮定を置く擬似的なパーセンタイル化を必須とする制約である。

### スコープ外の構造的論点

momentum_pt が中央密集型の分布になることで、総合スコア（業績40/モメンタム25/指標20/テーマ15）におけるモメンタム成分の効き方が設計配分どおりにならない可能性がある。これは本要件で扱う「分布仮定の精度向上」とは別軸の論点で、scaleパラメータの調整で部分的に緩和できる。本要件ではscale調整の余地を確保するに留め、配分の効き方の最適化は将来の検討事項とする。

## 2. ゴール

1. **rs_rel の分布仮定を対数正規分布に置き換える**: 実データの分布形状と整合する仮定にする
2. **scale パラメータを動的に実測する仕組みを導入する**: 相場環境の変化に追従可能にする
3. **個別銘柄の独立計算可能性を維持する**: ウォッチリスト+トリガー方式のシステム設計と両立させる
4. **scale 調整余地を残す**: 「実測どおり」「倍率調整」「下限保証」など、運用しながらチューニングできる構造にする

---

## 3. アーキテクチャ方針

### 個別銘柄独立計算の維持

momentum_pt の計算は、これまで通り銘柄ごとに独立して実行可能とする。新たに導入する分布パラメータ（loc, scale）は、market_db に事前にキャッシュされた値を参照する形式とする。

### キャリブレーションと個別計算の分離

分布パラメータの実測（キャリブレーション）と、個別銘柄の momentum_pt 計算は、別タイミング・別プロセスで実行されることを許容する設計とする。

```
[キャリブレーション処理]（低頻度）
  対象銘柄群の rs_raw / topix_rs_raw を集計
  → log(rs_rel) の loc, scale を実測
  → market_db['momentum_calib'] に保存

[個別銘柄の momentum_pt 計算]（毎日のウォッチリスト更新時）
  market_db['momentum_calib'] を参照
  → 対数正規分布CDFで rs_rel をパーセンタイル化
  → momentum_pt を更新
```

### キャリブレーション対象の限定

全銘柄を毎日更新しない制約があるため、キャリブレーションには「最近の rs_raw 値が揃っている銘柄」のみを対象とする。

- 直近 N 日以内に rs_raw が更新された銘柄を抽出
- N の具体値は実装時に決定（運用しながら調整可能）
- 古い rs_raw は市場環境を反映しないため除外する必要がある

### フォールバック方針

market_db['momentum_calib'] が存在しない、または不完全な場合は、デフォルト値（issue #104 の実測値ベース）にフォールバックして計算を継続する。これにより新規環境やデータ不足時も動作を保証する。

## 4. 基本設計

### 計算式の変更

#### 従来（正規分布、固定 scale）

```
momentum_pt ＝ 100 × CDF(rs_rel; 平均=1.0, 標準偏差=0.3)
```

CDF は累積分布関数（正規分布の上側確率の補数）。

#### 新仕様（対数正規分布、動的 loc/scale）

```
log_rs_rel ＝ log(rs_rel)
momentum_pt ＝ 100 × CDF(log_rs_rel; 平均=loc, 標準偏差=scale)
```

- loc, scale は market_db['momentum_calib'] から取得
- rs_rel ≤ 0 の場合は最低値（例: -10）にフォールバックして対数の発散を回避

### キャリブレーション対象の選定

| 項目 | 内容 |
|------|------|
| 対象 | 直近 N 日以内に rs_raw が更新された銘柄 |
| N の決定 | 実装時に決定（推奨レンジ: 7〜30日）。短すぎるとサンプル数不足、長すぎると環境追従性低下 |
| 除外条件 | rs_raw ≤ 0 の銘柄、TOPIX側のrs_rawが取得できていない場合 |
| 最小サンプル数 | 統計的に意味のある loc/scale を出せる下限を実装時に決定（例: 100銘柄以上） |

### market_db への保存

新規フィールド `market_db['momentum_calib']` を追加する。

| キー | 内容 |
|------|------|
| loc | log(rs_rel) の実測平均 |
| scale | log(rs_rel) の実測標準偏差 |
| sample_count | キャリブレーションに使った銘柄数 |
| updated_at | キャリブレーション実施日時 |
| n_days | 対象期間（直近N日） |

### キャリブレーション実施タイミング

**運用方針: 手動実行のみ。日次バッチや週次cronによる自動更新は行わない。**

自動更新を採用しない理由:

- loc/scale が変動すると、銘柄の rs_raw が同じでも momentum_pt が変わり、code_rank が動いてしまう
- 「銘柄の実力」ではなく「基準そのもの」の動きで評価が揺れるのは、ランキングの一貫性を損なう
- log(rs_rel) の loc は構造的にほぼゼロ、scale は市場のクロスセクション分散であり、週単位で意味のある変化はしない (動くのは月〜四半期スケール)

再校正のタイミング:

- 相場局面が大きく変わったとき (強気↔弱気の転換、ボラティリティ環境の大きな変化)
- Phase 2 切替時の初回校正
- フォールバック値 (loc=-0.058, scale=0.275) との乖離が継続的に大きいことを確認したとき

実行コマンド: `python make_stock_db.py calibrate_momentum`

### scale 調整余地の確保

実測 scale をそのまま使うか、調整して使うかは運用判断とする。実装としては「実測値を取得 → 調整関数を経由 → 最終 scale」という構造にし、調整方法を将来切り替えられるようにする。

調整方針の選択肢（実装時に1つを選び、必要なら切り替え可能にする）：

| 方針 | 内容 | 用途 |
|------|------|------|
| 実測値そのまま | scale = 実測σ | 分布形状への忠実さを優先 |
| 倍率調整 | scale = 実測σ × α (α ≥ 1) | 中央密集を緩和、配分25%の効きを強める |
| 下限保証 | scale = max(実測σ, 下限値) | 弱気相場での scale 過小化を防ぐ |

最初の実装は「実測値そのまま」とし、運用結果を見ながら必要なら他の方針に切り替える。

### フォールバック値

market_db['momentum_calib'] が利用できない場合のデフォルト値:

| パラメータ | デフォルト |
|-----------|-----------|
| loc | issue #104 の実測値（log(rs_rel)の平均） |
| scale | issue #104 の実測値（log(rs_rel)のσ） |

具体値は実装時に確定。当面は #104 の検証で得られた loc=-0.058, scale=0.275 を採用候補とする。

## 6. スコープ外

### 本要件で扱わないもの

- **経験ランク方式への全面移行**: システム設計の制約（全銘柄同時更新が無い）により採用不可
- **全銘柄を毎日同時更新する仕組みの構築**: アーキテクチャ全体の見直しになるため対象外
- **総合スコアの配分（業績40/モメンタム25/指標20/テーマ15）の変更**: 本要件は momentum_pt 算出ロジックのみを対象とする
- **rs_raw の計算式変更**: 13/26/39/52週加重平均の重み（[0.4, 0.2, 0.2, 0.2]）は維持
- **RSライン（生比率）系指標の実装**: 別要件 `rs_line_requirements.md` で対応

### 保留事項（運用しながら判断）

- **再校正の判断基準**: 「フォールバック値との乖離が何ヶ月続いたら再校正するか」の運用ルール (現状は手動判断)
- **対象期間 N（直近N日）の最終決定**: 7〜30日のレンジから運用結果を見て決定
- **scale 調整方針の最終選択**: 実測値そのまま運用 → 必要なら倍率調整・下限保証へ切り替え
- **配分25%の効き方の最適化**: scale 調整で対応するか、配分自体を見直すかは別途検討
