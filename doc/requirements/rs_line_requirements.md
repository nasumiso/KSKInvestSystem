# RSライン（生比率）ベースのモメンタム評価系 要件定義

> 既存の rs_rank（順位ベース）に対する補完指標として、オニール流のRSライン（銘柄株価/指数の生比率）を導入し、code_rank.csv の RS表示を直感的に読めるものに刷新する。
>
> 本要件定義は #103 と #105 を統合し、再構成したものである。
>
> issue: #155

---

## 1. 背景

### 現状のモメンタム評価系

Shintakane のモメンタム評価には、性質の異なる3つの指標が混在している。

| 指標 | データ性質 | 役割 |
|------|----------|------|
| `rs_rank` | 順位（0〜100） | 全銘柄中での相対順位 |
| `rs_rel = 銘柄rs_raw / TOPIX_rs_raw` | 比率（生値） | momentum_pt 算出の中間値 |
| `momentum_pt` | パーセンタイル（0〜100） | 総合スコアのモメンタム成分（25%配分） |

これらはいずれも「他銘柄との比較順位」を出すための指標であり、**個別銘柄の RSライン（=銘柄株価/指数の生比率系列）の形や推移そのもの**を見る指標ではない。

### オニール流 RSライン との違い

オニールが重視した RSライン は `銘柄株価 / 指数` の**生の比率系列**であり、用途が異なる。

- チャート上の**形・推移・新高値**を視覚的に読み取るためのもの
- 市場全体のトレンドを自動除去した**純粋な相対推移**を示す
- 特に**下げ相場で上がっているRSライン**の検出に適する
- 「株価のブレイクアウトより先にRSラインが新高値」がオニール流の最強セットアップ

既存の rs_rank（順位）と RSライン（生比率）は**別物の指標として共存させる**べきもので、片方が他方を置き換える関係ではない。

### 課題

#### 課題1: code_rank.csv の RS(20,5) 列が直感的でない

現状の RS(20,5) 列は `現在順位.20日前順位5日前順位` を文字列連結した形式（例: `99.8877`）で表示されている。

- 順位そのものを見せているだけで、**勢い（騰落率）が一目で分からない**
- 順位は相対値のため、「順位が88→99に上がった」と「絶対的な相対強さがどう変わったか」は別問題

#### 課題2: 「RSラインの形」を捉える指標が存在しない

新高値・ダイバージェンス・新高値先行性といった、オニール流の RSライン を活用した投資判断の材料が、現状のシステムでは提供できていない。

### #103・#105 の統合経緯

#103（RSライン評価ロジックの改良）は当初、対象データを既存の `rs_rank` としていた（案A: 正規化スロープ、案B: 新高値判定、案C: ダイバージェンス検出）。

一方 #105（オニール流RSライン）は、対象データを生比率の `rs_line` として独立に提案された。

検討の結果、#103 のアイディア（スロープ・新高値・ダイバージェンス）を**対象データを `rs_rank` から `rs_line` に切り替えて適用する**ことで、オニール本来の RSライン活用法と整合する形で統合できると判断した。本ドキュメントはこの統合方針に基づく要件を定義する。

統合の要点:

- #105 の「RSライン」概念を全体の基盤とする
- #103 の3つの評価ロジックを `rs_line` ベースで再構成する
- ただし #103 案B（日次20日新高値）と #105（週足20週新高値）は粒度が異なる別シグナルとして両方残す（ただし週足の必要性は Phase 3 着手時に再検討、§6 参照）

なお #104（momentum_pt の対数正規分布モデル化）は本要件と独立した改良であり、別PRで対応する。

## 2. ゴール

1. **RSライン（生比率）のデータ構造を構築する**: 日次系列を Phase 1 で構築。週足は Phase 3 着手時に必要性を再評価
2. **RSラインベースの勢い指標を提供する**: 短期/中期の騰落率
3. **RSラインの新高値判定を提供する**: 日次（20日新高値）。週足は Phase 3 着手時に必要性を再評価
4. **株価とRSラインのダイバージェンスを検出する**: 方向の食い違いを定量化
5. **株価ライン × RSライン の可視化を実現する**: 最終ゴール、新高値・ダイバージェンスの直感把握

## 3. アーキテクチャ方針

### 既存指標との役割分担

既存の rs_rank・momentum_pt とは**補完関係**として共存させる。

| 指標 | 性質 | 役割 |
|------|------|------|
| `rs_rank`（既存） | 全銘柄中の順位 | 銘柄選定（他銘柄との比較） |
| `momentum_pt`（既存） | 正規化パーセンタイル | スコアリング25%配分 |
| **RSライン系（新規）** | **個別銘柄の生比率推移** | **形・新高値・ダイバージェンスの視認** |

### データの独立性

新規データ構造は既存のスクレイピングパイプラインに最小限の追加で済むよう設計する。

- 銘柄側日次データ: 既存の `price_log` を流用（`price.py` の `LOG_DAY` を 20→25 に拡張、20日前比較に必要な21件 + 4日のバッファ）
- 指数側日次データ: TOPIX の日次終値系列を `_calc_daily_indicators` 出力に `price_log` キーを追加して `market_db["topix"]` に保存
- 週足データ（銘柄側・指数側）: Phase 1 では実装しない。Phase 3 着手時に必要性を再評価（§6 参照）

### rs_line を銘柄DBに永続化しない方針

`rs_rank_log` のような順位指標は過去の全銘柄ランキングを再現できないため日次蓄積が必要だが、`rs_line` は **銘柄終値系列と TOPIX 終値系列さえあれば過去遡及で計算可能**である。したがって rs_line そのものは銘柄DBに保存せず、必要時に都度計算する純粋関数 `compute_rs_line()` として提供する。

### スコアリングへの組み込みは行わない

新規RSライン系指標を業績40/モメンタム25/指標20/テーマ15の総合スコアに組み込むことはしない。

- スコアリングのモメンタム成分は引き続き既存の momentum_pt が担う
- 新規指標は code_rank.csv の表示・補助指標として機能させる

### 加重・正規化を行わない原則

オニール流 RSライン の意図は「形の視認性」と「時間軸の前後関係」にある。これらを保つため、`rs_line` 系列は**生の比率のまま保持し、加重平均・正規化を行わない**。

## 4. 基本設計

### 新規データ構造

#### 日次 rs_line 系列

- 定義: `銘柄日次終値 / TOPIX日次終値` の履歴
- 保持期間: **過去25営業日分**（20日前比較に必要な21件 + 4日のバッファ）
- 格納先: **永続化しない**。`make_stock_db.compute_rs_line()` で都度計算

#### 週足 rs_line 系列

Phase 3 着手時に必要性を再評価する。Phase 1+2 のスコープ外（§6 参照）。

### 新規指標

| 略号 | 名称 | 計算式 | 用途 | Phase |
|-----|------|--------|------|-------|
| **A** | RSライン短期騰落率 | `(rs_line[今日] - rs_line[5日前]) / rs_line[5日前] × 100` | 直近5日のRSラインの勢い | 2 (実装済) |
| **B** | RSライン中期騰落率 | `(rs_line[今日] - rs_line[20日前]) / rs_line[20日前] × 100` | 直近20日のRSラインの勢い | 2 (実装済) |
| **C** | RSライン短期新高値 | 日次rs_lineが過去20日の最高値（厳密）かのbool。タグ列に `R高` を表示 | 短期動意の確認 | 3 (実装済) |
| ~~**D**~~ | ~~RSライン長期新高値~~ | ~~週足rs_lineが過去20週の最高値かのbool~~ | ~~オニール流リーダー候補検出~~ | **不実装** |
| ~~**E**~~ | ~~株価×RSラインダイバージェンス~~ | ~~株価騰落率と rs_line 騰落率の符号食い違い（20日前比、閾値±3%）~~ | ~~強気/弱気ダイバージェンスの検出~~ | **不実装** |

#### D を実装しない理由

オニール原典で「週足20週新高値」が特に強調された具体的指標である根拠が薄く、原典が重視するのは 52週RS Rating（順位）と週足チャート上での視覚的な新高値（期間は文脈次第、52週が中心）であるため。Phase 3 着手時に再評価し、実装しない判断とした。週足 rs_line データ基盤も本要件全体のスコープから外す。

#### C の判定: 厳密比較 (>) を採用

「>=」だと横ばい（同値）日に毎日 True が立ち、当日発生シグナルとしての意味が失われるため、`current > max(rs_line[1:lookback+1])` の厳密比較を採用。連日同値の場合は最初の更新日のみ True。

#### E の日付アライン

`rs_line` は TOPIX と日付一致した日だけが残るので、`rs_line[offset]` の日付と銘柄 `price_log[offset]` の日付がズレる可能性がある（休場日、TOPIX 欠損等）。これを避けるため、`rs_line[offset]` の日付を基準に銘柄 `price_log` から同日終値を引き直してから騰落率を算出する。

#### A・B の計算方式について

当初案では「現在値と直近5日/20日移動平均の乖離率」（MA乖離率方式）を採用する予定だったが、以下の理由で**単純騰落率方式**（5日前比 / 20日前比）に変更した。

- MA乖離率方式は B（中期）の計算に「直近20日のMA」が必要 → 計40日分の rs_line データが必要
- 単純騰落率方式なら 21日分で済み、データ保持コストが半減
- 「20日前比でどれだけ動いたか」は CSV を見ただけで意味が直感的に読める
- ノイズ耐性は「rs_line 自体が日次比率なので元々ノイジー」の前提で許容

### code_rank.csv の表示変更

#### 現状

```
モメンタム(現在.5/20日過去) 列: 99.8877 形式（現在順位.20日前順位5日前順位）
```

#### 新仕様

```
モメンタム(現在.20日比/5日比) 列: 99.+12/+5 形式（rs_rank.中期B%/短期A%）
```

- 第1要素: 現在の rs_rank（既存維持）
- 第2要素: B = RSライン中期騰落率（%表示、符号付き整数）
- 第3要素: A = RSライン短期騰落率（%表示、符号付き整数）

新高値マーカー（C/D）の埋め込みは保留事項とする（運用しながら表示形式を検討）。

### #104 との関係

#104（momentum_pt の対数正規分布モデル化）は本要件と**完全に独立**である。

- #104 は既存の `momentum_pt` 算出ロジックの統計的精緻化
- 本要件は新規の RSライン 系指標の追加
- 両者は同時並行で実装可能、依存関係なし

## 5. 実装順序

| Phase | 内容 | 該当指標 | 主な対象モジュール |
|-------|------|---------|------------------|
| **1** | 日次 rs_line データ構造の構築 | データ基盤 | price.py（TOPIX側 price_log 追加, LOG_DAY 拡張）, make_stock_db.py（compute_rs_line） |
| **2** | 騰落率指標 + code_rank.csv 表示変更 | A, B | make_stock_db.py（compute_rs_line_changes, get_rs_line_changes_expr）, code_rank出力 |
| **3** | 新高値判定（および週足データ基盤の必要性再評価） | C, D | make_stock_db.py |

| **5** | 株価×RSライン可視化 | 最終ゴール | 新規（Webビュー等） |

Phase 1 と Phase 2 は同一PRで同時実装する（データ基盤とその初の利用箇所が密接なため）。Phase 3〜5 は別 PR。

## 6. スコープ外

### 本要件で扱わないもの

- **スコアリングへの組み込み**: 業績40/モメンタム25/指標20/テーマ15 の総合スコアに新規RSライン系指標を組み込むことはしない
- **momentum_pt の改良**: #104 で別途対応
- **既存 rs_rank の廃止または計算ロジックの変更**: 既存指標は維持
- **既存 `rs_rank_log` / `update_rs_rank` / `get_rank_log_expr` の削除**: Phase 3〜5 で再利用の可能性があるため、現時点では残置（dead code）

### 保留事項（運用しながら判断）

- **週足 rs_line データ構造の構築**: オニール原典で「週足20週新高値」が特に強調された具体的指標である根拠が薄く、原典が重視するのは 52週RS Rating（順位）と週足チャート上での視覚的な新高値（期間は文脈次第、52週が中心）。Phase 3 着手時に C/D の必要性と合わせて再評価する
- **新高値マーカー（C/D）の code_rank.csv 表示形式**: 現時点では表示しない方針だが、運用しながら表示の必要性を判断
- **新高値マーカーの先行性分類**: 「RSライン新高値かつ株価まだ新高値でない」のような細分化は保留。Phase 5 の可視化で代替できる可能性もあるため
- **ダイバージェンス（E）の閾値・判定期間**: 実装後の運用結果を見ながら最適化
- **可視化UIの形態**: 既存 webapp 統合 / 別画面 / 外部ツール連携
