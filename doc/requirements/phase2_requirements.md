# Phase 2 要件定義：銘柄調査Webビュー

> research_shelve + stocks_shelve のデータを統合し、ブラウザで銘柄調査・比較を行う

---

## 1. 背景

### Phase 1で実現されること

- research_shelveに849銘柄分の時系列スナップショットと手動メモが蓄積される
- 決算更新時にスナップショットが自動追記される
- CLIで個別銘柄の閲覧とバックアップが可能

### Phase 2で解決する課題

- **深掘り分析の効率**: CLIやCSVでは、1銘柄の時系列推移を俯瞰したり、複数銘柄を横並びで比較するのが困難
- **手動メモの入力手段**: Phase 1のCLIでもメモ編集は可能だが、決算を見ながらブラウザ上でメモを書ける方が自然なワークフロー
- **code_rank.csvとの役割分担**: 一覧性のあるランキング表示はcode_rank.csvがすでに担っている。Webビューは「銘柄を指定しての深掘り」に特化する

---

## 2. ゴール

1. **銘柄詳細ビュー**: 1銘柄の全情報（stocks_shelveの最新データ + research_shelveの時系列・メモ）を1画面で俯瞰できる
2. **銘柄比較ビュー**: 複数銘柄の指標推移を横並びで比較できる
3. **メモ編集**: ブラウザ上で手動メモ（総合評価、IR分析コメント、メモ・総括、四季報等）を編集・保存できる

---

## 3. アーキテクチャ方針

### 一体型Webアプリ

シンプルさを優先し、Webフレームワーク＋テンプレートエンジンの一体型構成とする。

```
[ブラウザ]  ←HTTP→  [Webアプリ]  ←直接読み書き→  [research_shelve]
                        ↑
                    直接読み取り
                        ↓
                   [stocks_shelve]
```

- Phase 1のResearchDBモジュールをそのままimportしてデータアクセスする
- stocks_shelveの読み取りも既存のShelveDBクラスを直接利用する
- API層は設けず、リクエスト→DB読み書き→画面レンダリングを1プロセスで完結させる

### 技術選定の方針

- **フレームワーク**: Pythonベース（FastAPI/Flask等）。Shintakaneと同一リポジトリ・同一言語で、shelve DBへの直接アクセスが自然にできる
- **フロントエンド**: テンプレートエンジンまたは軽量なSPA。実装時の判断に任せる
- **Shintakaneの日次パイプラインとは独立プロセス**: Webアプリは日次バッチの実行には関与しない

### 排他制御

- Shintakaneの日次バッチ（19時実行）がstocks_shelveを更新し、決算検知時にresearch_shelveにスナップショットを追記する
- Webアプリからのresearch_shelveへのメモ書き込みと、日次バッチのスナップショット追記が競合する可能性がある
- Phase 1のResearchDBモジュールが提供するロック機構で対応する

### 将来展望：非ローカル運用

Phase 2時点ではローカル運用のみをスコープとする。将来非ローカル化が必要になった場合は、データアクセス部分をAPI化するリファクタリングで対応する。一体型で作っておいても、DB操作がResearchDB/ShelveDBクラスに集約されていれば、API層を後から挟む改修は比較的軽い。

## 4. 画面構成

### 4-1. 銘柄詳細ビュー（主機能）

code_sを指定して1銘柄の全情報を1画面に表示する。

**表示する情報**:

| セクション | データソース | 内容 |
|-----------|------------|------|
| ヘッダー | stocks_shelve + research_shelve | 銘柄名、セクター、総合評価、最新スコア・順位 |
| 最新指標 | stocks_shelve | 時価総額、PER、ROE等の最新値、トレンドテンプレート、シグナル |
| 業績スナップショット時系列 | research_shelve | IR分析の定量データとコメントを時系列で表示 |
| 指標スナップショット時系列 | research_shelve | クォリティ指標の推移 |
| 理論株価乖離率時系列 | research_shelve | 理論株価乖離率の推移 |
| 手動メモ | research_shelve | メモ・総括、OpenWork、ジムクレイマー、四季報コメント（編集可能） |

**ポイント**:
- スプレッドシートの「1行に全情報を詰め込む」形式から、「1銘柄1ページで時系列を縦に展開する」形式への転換
- 時系列データは表形式で表示し、成長率の変化やPERの推移が一目でわかるようにする
- 手動メモはインライン編集可能にし、保存ボタンでresearch_shelveに書き込む

### 4-2. 銘柄比較ビュー

複数のcode_sを指定して、主要指標を横並びで比較する。

**ユースケース**:
- 同業種・同テーマの銘柄の成長率やバリュエーションを比較して投資候補を絞り込む
- 保有銘柄と候補銘柄の指標を並べて入れ替えを検討する

**表示する情報**:
- 選択した銘柄の最新指標の横並び比較
- 時系列での推移比較（同一指標を複数銘柄で重ねて表示）

### 4-3. 銘柄検索・選択

code_sの直接入力、または銘柄名・テーマ・評価でのフィルタリングにより、詳細ビュー・比較ビューに遷移する導線。

一覧表示の機能はcode_rank.csvが担うため、ここでは「目的の銘柄にたどり着く」ための最低限の検索機能を提供する。

---

## 5. スコープ外

- **保有銘柄の管理機能**: 別途タスクで対応
- **code_rank.csv相当の一覧・ランキング表示**: code_rank.csvが引き続きこの役割を担う
- **API層の分離**: ローカル運用では不要。非ローカル化時にリファクタリングで対応
- **認証・権限管理**: ローカル運用では不要
- **モバイル最適化**: 初期はPC利用前提

---

## 6. Phase 1との依存関係

Phase 2はPhase 1の以下の成果物に依存する：

- **research_shelve**: レコード構造、スナップショットの蓄積、手動メモのフィールド定義
- **ResearchDBモジュール**: データアクセス、ロック機構
- **移行済みデータ**: 849銘柄分のスナップショット＋メモ

Phase 1が完了し、CLIでの運用が安定してからPhase 2に着手する。
