# AI開発原則

Shintakane は Claude Code・Codex などの AI と一緒に開発する。
このファイルは、AI と開発するときに**何を文書に書き、何を書かないか**と、開発での AI の使い方をまとめる。
投資判断での AI の使い方は [AI投資活用戦略.md](AI投資活用戦略.md) を参照。

## 原則: AI がコードから推測できないものだけを書く

AI はコードから構造を復元できる。構造を書き写した文書はほとんど情報を増やさない。
一方で AI が絶対に推測できないものがあり、それが書かれていないと「正しく動くが意図と違うもの」が出てくる。

| 推測できる (書かない) | 推測できない (書く) |
|---|---|
| クラス・モジュール構成、ディレクトリ構成 | 用語の定義 |
| 関数シグネチャ、定数値、DB キー一覧 | 不変条件 (どこで守るかまで) |
| 既存処理の手順 | 却下した案とその理由 |
| データ構造 (コードに定義がある) | 外部世界の制約 (証券会社CSVの仕様、株探の挙動、運用機の事情) |
| 状態遷移 (定数と分岐から追える) | UI のレイアウト・画面遷移 |

実装の詳細はコードの docstring を正とし、文書には書き写さない。

| 書くもの | 置き場所 |
|---|---|
| 用語の定義・不変条件 | [用語集と不変条件.md](用語集と不変条件.md) |
| 却下した案とその理由 | [decisions/](decisions/README.md) |
| データフロー・責務・設計意図・画面遷移 | [アーキテクチャ.md](アーキテクチャ.md) |
| 外部世界の制約・運用手順 | [運用手順.md](運用手順.md) |
| 外部に出す約束・判定ロジックの詳細仕様 (MCP ツール、CLI、市場ステート) | [spec/](spec/) |

紹介資料・PDF・俯瞰図・説明用の図は正ではない。必要になったときに正のテキストから生成し、使い終わったら捨てる。

## 陥りやすいこと

- **腐った文書は無いより悪い。** 人間は「これ古いな」と飛ばすが、AI は書いてあることを信じて実装する。作る価値があるかではなく、**変更のたびに更新され続けるか**で判断する。完了した計画書や古い要件定義を残さない
- **不変条件を1層だけで守らせない。** 「〜は必須」とだけ書くと、AI は画面の検証だけ実装して完了と言う。UI / サービス / DB のどこで守るかまで書く
- **文書はコード変更と同じ PR に同梱する。** 仕様を変えた PR で、該当する正規ドキュメントも直す
- **モジュール・画面ごとの設計書は作らない。** 構造はコードから復元できるので情報が増えず、更新が止まった時点で害になる
