# #594 資産の復元と資金管理の比較

着手順 (2026-11-26 決定): **1. 資産の復元 → 2. 比較 → #593 の実装**。この計画書は **1. 資産の復元** を詳しく書く。2 は 1 の結果を見てから、この計画書に足す。

## ゴール

2025-01-06〜直近の営業日について、次の日次の系列を作り、2 の比較と #593 の両方で使えるようにする。

| 系列 | 定義 | 使い道 |
|---|---|---|
| 運用総額 P_t | Σ \|建っている株数\| × 終値 (現物・信用買い・信用売り、全証券会社) | 実際の倍率 |
| 売買損益 PnL_t | その日の値動きと約定で生じた損益 (入出金・手数料・金利・配当を含まない) | 張る量を変えたときの再計算の元 |
| 保有の日次リターン r_t | PnL_t ÷ P_{t−1} | 倍率を変えたシミュレーション (#594 本文の「全体の倍率だけを変えたとみなす」) |
| 自己資本 E_t | 基準点の自己資本 + 基準点からの PnL の累計 (下の「決めること 1」) | 実際の倍率 L_t = P_t ÷ E_t、高値からの下落率、下方ボラ |

E_t は入出金を含めない (損益の累計で動かす) ので、「入出金を除く」は作り方で満たされる。

## 方法: 約定から日ごとに値洗いする

往復行 (`build_round_trips`) ではなく、約定 (`ps.list_fills()`) を**証券会社 × 銘柄 × 向き (買い玉・売り玉)** ごとの**符号つき株数**で積み上げる。

- 買い玉: 現物買い・信用新規買い +、現物売り・信用返済売り −。**現引は 0** (信用から現物への振り替えで、持っている株は変わらない)
- 売り玉: 信用新規売り −、信用返済買い +
- 向きを分けるのは、同じ銘柄の買いと空売りを同時に持つと銘柄単位では相殺され、P_t が小さく出るため (実例: 9984 の 2026-05-20〜22。現物買いと空売りが重なった)
- 証券会社も分けるのは、検証 2 で日次ログと同じ範囲 (楽天・SBI) だけを取り出すためと、#593 で追証を証券会社ごとに見るため
- PnL_t = Σ_玉 [ q_{t−1} × (c_t − c_{t−1}) + Σ_その日の約定 Δq_f × (c_t − p_f) ]
  - q は前日引け時点の符号つき株数、c は終値、Δq_f と p_f は約定の株数 (符号つき) と単価
- 往復行を使わない理由: 期首持ち越しの玉は建値が分からず、`open_lots_at` は「建値不明」で落とす。値洗いなら建値は要らず、株数と約定単価だけで済む

### 期首持ち越し

約定の取込は マネックス 2024-12-27〜、楽天 2025-01-06〜、SBI 2026-03-04〜 (運用機で確認、2026-11-26)。取込より前に建てた玉は、最初の売りの時点で株数がマイナスになる。

- 買い玉ごとに、約定を積み上げた株数の最小値がマイナスなら、その分を**起点日 (2025-01-06) から持っていた**とみなす
- 期首から持ち越した売り玉は考えない。空売りは 2026-02 以降の3回 (2317・9682・9984) だけで、どれも新規売りの約定が取り込まれている (運用機で確認、2026-11-26)。返済買いが新規売りより多い銘柄があれば、計算を止めて知らせる
- 起点日に持っていた玉は、起点日の終値で値洗いを始める (起点日より前の損益は数えない)
- 一度も売っていない持ち越しの玉は見えない。下の検証 3 で、いまの保有株数と比べて見つける

### 分割・併合

- yfinance の終値 (`auto_adjust=False` の Close) は、後の分割で過去の値がさかのぼって調整される (配当では調整されない)
- 約定の株数・単価を、yfinance の分割情報で**全部の約定 (信用・現引も)** いまの株数の基準に直す。`_apply_split_adjustments` は現物だけを換算し、登録済みの分割しか見ないので使わない
- `ps.list_fills()` は換算前の生の約定なので、二重には換算しない

### 終値

- 月次の振り返りの `_fetch_closes` と同じく、yfinance から `auto_adjust=False` で取る。期間だけ起点日〜直近に広げる
- 休場日・取れない日は**直前の終値を持ち越す** (その日の値動きは 0 とし、次に取れた日にまとめて出る)。保有中の銘柄を途中で外すと P_t と以後の系列が不連続になるので、外さない
- 7日を超えて持ち越した銘柄と期間 (売買停止・上場廃止など) は一覧に出す。保有中に一度も終値が取れない銘柄があれば、計算を止めて知らせる

## 決めること

### 1. 自己資本の基準点 (ユーザーに聞く)

r_t は基準点なしで出せるが、倍率 L_t と下落率には自己資本の水準が要る。

- **推奨: 月末の自己資本を、ユーザーの記録 (投資日記・シートなど) から入れる。** 月ごとに「記録の差 − PnL の累計の差」が残差になり、入出金・手数料・金利・配当がまとめて見える。残差が大きい月は入出金とみなし、E_t をその月から段差で合わせる。これは #593 の「入出金をどう検出するか」の答えにもなる
- 代案: 基準点を1つ (例: 2026-11 の保証金率の入力日) にし、そこから前後に PnL の累計だけで伸ばす。入出金があった期間は倍率がずれる
- 「自己資本」の定義は、2 の比較では**純資産 (現金 + 現物時価 + 信用の評価損益)** にする。推定維持率の G (受入保証金、代用は 0.8掛け・評価益は数えない) とは別物で、#593 でどちらの物差しにするかを決める

### 2. 置き場所

- 計算は `scripts/equity_history.py` に置く (約定・終値・分割を受け取る純粋関数 + 取得と保存の CLI)。#593 で毎日の記録に同じ関数を使う
- 結果は金額を含むので、リポジトリではなく `DATA_DIR/analysis/equity_history.json` に保存する。比較の結果 (割合と結論) は `doc/投資メモ分析/レビュー/` に残す

## 検証 (この3つが合えば 2 に進む)

1. **月ごとの損益**: 2026-04〜10 の月ごとの PnL の合計を、月次の振り返りの「実現 + 含みの増減」(中間レビューの表: 4月 +316万 〜 10月 −305万) と比べる。月次の振り返りは往復行が作れない取引を外しているので完全には一致しない。差が月 ±5% を超えたら原因の銘柄を出して確かめる
2. **運用総額**: 2026-08-29 以降の P_t のうち**楽天・SBI の買い玉だけ**を、日次ログ (`exposure_log.json`) の `total_value` と比べる (日次ログは楽天・SBI の残高 CSV の買い玉だけを数える)。差が 1% を超える日を出す。この期間にマネックスの玉や売り玉が残っていれば、その額も並べて出す
3. **最終日の株数**: 直近の営業日の銘柄ごとの株数を、1保 の保有株数と比べる。食い違う銘柄 (見えない持ち越し・分割の換算ずれ) を一覧にして、直すか外すかを決める

テスト (`tests/test_equity_history.py`、parametrize で3本以内): 同じ日の買いと売り、現引、分割をまたぐ約定、空売りで、PnL と株数が手計算と一致すること。

## 対象外とするもの

- 手数料・信用金利・配当・貸株料: PnL に入れない。月末の基準点を入れれば残差に出る (年数十万円規模なら、倍率の比較の結論は変わらない見込み)
- 楽天・SBI・マネックス以外の口座、NISA の区別: P_t には入れるが、代用・追証の計算はしない (2 の比較は倍率と下落率で行う)
- 日経VI の取得: 2 の比較で扱う
