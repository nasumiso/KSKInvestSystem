# #535 信用評価損益率を /market の評価と運用比率の目標の段に反映する

## 背景

- 信用評価損益率 (信用買い建玉の平均含み損益率、2市場、週次) は `credit_balance.json` に取得済み。/market には値・1週前比・4週前比と、−3% 以上「天井圏」/ −15% 以下「底値圏」のバッジだけを出している (`make_market_db.py:1319` `_credit_rating_html`)
- 運用比率 (`exposure_guide.py`) では `exposure_log.json` に参考値として記録しているだけで、目標の段には使っていない
- ユーザーはこの指標を信頼できると考えており、F&G と同じく「Extreme のときに逆張りで感情を補正する」材料にしたい
- 手元の履歴は 30 週 (2026-03-27〜10-23)、範囲は −13.5%〜+1.47%、中央値 −5.3%。−15% 以下の週はまだ無い。閾値は自前データで校正できないので一般的な目安を使う

## 仕様

### 1. /market の評価列 (5段階、F&G と同じ配色)

| 損益率 | 表記 | CSS (既存の fng-rating) |
|---|---|---|
| −3% 以上 | 天井圏 | `fng-rating-extreme-greed` |
| −3〜−6% | 強気 | `fng-rating-greed` |
| −6〜−10% | 中立 | `fng-rating-neutral` |
| −10〜−15% | 弱気 | `fng-rating-fear` |
| −15% 以下 | 底値圏 | `fng-rating-extreme-fear` |

- 境界: `>= -3` 天井圏、`<= -15` 底値圏 (現行と同じ向き)。間は `> -6` 強気、`> -10` 中立、それ以外は弱気
- 弱気・底値圏で、前週 (history の1つ前) より値が上がった週は「↗改善」を添える
- 閾値は 1 か所 (`margin_estimate.py`) に定数で置き、/market と運用比率で共有する

### 2. 運用比率の目標の段 (`margin_estimate.target_step`)

現行: 感情スコアが主。F&G が Extreme (<25 / >=75) なら逆張りで ±1、それ以外の日は市場ステートで攻める側に上限。

変更後:

| 信用評価損益率 | 補正 |
|---|---|
| −3% 以上 (天井圏) | +1 (守る側) |
| −15% 以下 (底値圏) **かつ前週より改善** | −1 (攻める側) |
| それ以外 / 取れない | 0 |

- **F&G と信用は重ねない**。それぞれの向き (−1 / 0 / +1) を出し、
  - どちらかだけが ±1、または両方が同じ向き → その向きに 1 段だけ
  - 向きが逆 (F&G −1 と信用 +1 など) → 打ち消して 0
  - 補正が 0 でないとき (逆張りが効いた日) は市場ステートの上限をかけない。打ち消して 0 の日と、両方 0 の日は上限をかける
- 底値圏は「前週より改善」を条件にする理由: 底で早く張ると −20〜−25% まで突き抜けたときにレバレッジをかけたまま実損になる。天井で早く落とすのは機会損失だけ。痛みが非対称なので底の側だけ厳しくする
- 「前週」は history の1つ前のエントリ。最新と前のエントリの日付が 10 日を超えて離れていたら改善の判定はしない (補正なし)
- 鮮度: 最新値は既存の `read_credit_eval_rate` (10 日以内) をそのまま使う。前週値も同じ関数から返す

### 3. 保有サマリーの表示

- 「感情 ＋ F&G ＝ スコア → 目標」の並びに信用を足す: 「感情 −2 ＋ F&G [Extreme Fear] −1 ＋ 信用 [弱気] ±0 ＝ −3 → 目標 …」
- 信用のラベルは /market と同じ5段階の表記・同じ色。改善中なら「↗」。値と前週値はツールチップ
- 打ち消しや重ねなかったことは `step_parts` の説明に出す (例「F&G Extreme Fear (22) と信用 底値圏で改善 (−16.2%) で −1 (重ねない)」)
- `_target_chain` (`webapp/routes/portfolio.py`) が target_step と同じ決まり方を再計算しているので、合わせて直す

### 4. 日次ログ

- `exposure_log.json` の `credit_eval_rate` を「判定には使わない参考値」から外し、`step_parts` に信用の寄与が残るようにする。前週値も記録する (後から改善判定を再現できるように)

## 変更箇所

- `scripts/margin_estimate.py`: 信用の閾値定数、`credit_label(rate)` (5段階の名前)、`credit_step(rate, prev_rate)` (−1/0/+1)、`target_step` に `credit` 引数を足し F&G との合成を入れる
- `scripts/exposure_guide.py`: `read_credit_eval_rate` が前週値も返す。`evaluate_target` / `build_evaluation` / `build_daily_entry` に渡す
- `scripts/make_market_db.py`: `_credit_rating_html` を5段階 + 改善印に (前週値を渡す)
- `scripts/webapp/routes/portfolio.py` `_target_chain`、`templates/_summary_inputs.html`: 信用の表示
- 文書: `doc/spec/推定維持率仕様.md` (目標の決まり方)、`doc/アーキテクチャ.md` §9、`doc/用語集と不変条件.md` の運用比率の行、判断記録 (`doc/decisions/` に新規。10/24 の判断のどこを変えたか)

## テスト (5本以下)

1. `test_target_step` の parametrize に追加: 信用天井圏で +1 / 底値圏で改善 −1 / 底値圏で悪化中は 0 で市場ステートの上限 / F&G と同じ向きでも 1 段だけ / 逆向きで打ち消し (上限がかかる)
2. `credit_step` の境界 (−3.0、−15.0、前週日付が離れている) を parametrize で
3. `_credit_rating_html` の5段階と改善印を parametrize で

## 12月末の検証との関係

10/24 の判断の見直し条件 (2026-12 末に `exposure_log.json` で「F&G が Extreme の日・感情スコアが 0 以外の日に運用総額が適正エリアの方向へ動いたか」) は、`step_parts` で信用が効いた日を区別できるので、分けて評価できる。信用だけが Extreme で F&G が Extreme でない日は多くない見込み。
