# #480 感情スコアと F&G から目標維持率を出し、運用総額の適正エリアを維持率ベースにする

基準運用額 (2,650万) による運用比率ガイド (#362) を廃止し、推定維持率 (#527) を物差しにする。
目標は感情スコア (自己申告 7段階) と日本版 F&G で決め、市場ステートは上限と参考表示に使う。

## 決まった仕様 (2026-10-23 ユーザー確認済み)

### 資産の定義
- シートの「資産比」の資産 = **証券口座 (楽天+SBI) の自己資本**。シートの % (自己資本 ÷ 建玉) を、そのまま**目標の維持率**として使う
- 実データ (10/23): 維持率 56.7%、自己資本 ≈ 1,206万、運用総額 2,310万 (レバ 1.92倍)。基準運用額 2,650万は使わない

### 目標の段 s (−3〜+3)
1. 感情スコアの最新値。入力から 5 営業日を過ぎた・未入力なら 0 (中立) として扱い、促す
2. F&G (日本版) で調整
   - Extreme Fear (< 25): s − 1 (逆張り。市場ステートの上限はかけない)
   - Extreme Greed (≥ 75): s + 1 (逆張り)
   - 25〜74: 市場ステート (保有額加重。今の `weighted_state` / `fallback_state`) で攻める側に上限をかける
     - 調整局面: s = max(s, 0) / 上昇圧力下: s = max(s, −1) / 上昇確定: 上限なし
   - F&G が鮮度切れ (`read_fng_jp` が None) なら 25〜74 と同じ扱い
   - 市場ステートが取れない (指数が全部鮮度切れ) ときは、上昇圧力下と同じ上限 (s ≥ −1) をかけて注記する。
     **今のように評価ごと出さない・日次ログを飛ばす早期終了はやめる** (F&G が Extreme の日はステートを使わないので、その日が記録から抜けると効果検証ができない)
3. ±3 で止める

### 目標の維持率と適正エリア
- 段 → 目標維持率 (シート正本): −3: 50 / −2: 60 / −1: 70 / 0: 80 / +1: 90 / +2: 100 / +3: 120 (%)
- 適正エリア = 目標維持率 ± 5pt
- 楽天+SBI の合算値 (G = 受入保証金、B = 信用建玉合計、S = 現物時価、M = 信用建玉の時価) で計算する
- 建玉の目標 B_t = G ÷ 目標維持率 (B は維持率の分母どおり建単価ベース)。**建玉の増減は信用で行う前提**
- 運用総額 P は残高 CSV の S + M (時価)。B_t との差を時価に直して P の目標にする
  - 増やす (B_t > B): 新規建ては時価で建つので ΔP = B_t − B
  - 減らす (B_t < B): 建玉を比例で返済するとみなし ΔP = (B_t − B) × M ÷ B
  - 返済時の評価益の実現で G が増える分は入れない (減らす量がやや多めに出る。spec の近似の限界に書く)
- 適正な運用総額 = P + ΔP。エリアの両端は目標維持率 +5pt (少なめ側) と −5pt (多め側) で同じ式から出す
- 画面の運用総額 (1保 レコードの数量 × 終値、`summarize_hold_positions`) と残高 CSV の S + M が 1% 以上ずれたら、
  「保有銘柄の数量と残高 CSV がずれています」と注記する (10/23 はどちらも 2,310万で一致)。判定とバーの位置は S + M を使う
- 楽天・SBI 以外の証券会社の残高は G・B・S・M に入らない (今は無い)
- **残高 CSV に保有がある証券会社は、すべて推定が成立したときだけ**適正エリアを出す。1社でも推定できなければ
  (基準値なし・CSV 不備・信用建玉なし等) 適正エリアと判定を出さず、欠けた証券会社と理由を注記し、日次ログには
  area_* を null で残す。片方だけの G・B・S・M で全体の過不足を出さないため。保有が無い証券会社は対象外。
  合算の推定維持率の表示 (#527) は今のまま (成立した証券会社だけで出し、欠けた方を注記)
- **追証の下限**: 全保有が一律に 20% 下がっても追証 (20%) にならない建玉まで。
  (G − 0.2B) ≥ 0.2 × (B + 0.8S) より B ≤ (G − 0.16S) ÷ 0.4。多め側の端をこれで頭打ちにし、頭打ちになったら注記する
- 判定: 運用総額がエリアより多い = over / 少ない = under / 内側 = within

### 表示 (保有タブのサマリー)
- 今の運用総額のバーはそのまま。横軸は運用総額 (万円)、目標帯を適正エリアに置き換える。「基準」の線は「中立 (80%)」の位置に置き換える
- 見出し行: `運用総額 2,310万 | 目標 維持率 70% (感情 0 → F&G 恐怖 −1) | 適正 1,920〜2,110万 | −200万` のように、段の決まり方と過不足を出す
- 市場ステートのバッジは参考として残す (ツールチップに「F&G 25〜74 のときの上限」と書く)
- 推定維持率が出ない (基準値なし等) 日は、今の「指標が揃わず目標レンジ非表示」と同じ扱いで運用総額だけ出し、理由を注記する
- 過熱モディファイア (信用評価損益率・F&G ≥ 75 で上限を削る) は廃止 (F&G は段の調整に移る)

### 感情スコアの入力
- サマリーに `感情 0 中立 (10/23)` と「入れる」を出す。押すと 7段階のボタン (シートの状態名と自己申告の目安をツールチップ) と任意の一言欄
- `POST /portfolio/emotion` で保存。portfolio_shelve に `emotion:<ISO 日時>` = {date, score, note, recorded_at} として追記 (同日の再入力は最新を採用)
- 今日のアクションに `感情スコア: 未入力` (5 営業日を過ぎたら) を出し、保有タブへリンク

### 日次ログ (exposure_log.json)
- 記録する項目を置き換える: date, emotion_score (と入力日), fng_jp, state (参考), step, target_rate, margin_rate_pct, total_value, area_lower, area_upper, floor_capped, position
- 旧項目 (ratio_pct, base_amount, range_*, modifiers_applied) は新しい行には書かない。既存の行は残す
- 月次レビュー (`trade_review.py`) の `exposure` 集計は、新しい行があれば `margin_rate_pct` の最小・最大と、over の日数 (旧: 調整局面で over の日数) に切り替える。旧行だけの月は従来どおり

### 成功の基準 (提案 3)
- 2026-12 末の仕様レビューで、日次ログから「F&G が Extreme の日・感情スコアが 0 以外の日に、運用総額が適正エリアの方向へ動いたか」を見る。動いていなければ表示ではなく仕組みを見直す。判断記録と spec に書く

### やらないこと
- 行動との突き合わせ (#480 やりたいこと 3)。記録が貯まったら最初に扱う (#480 に残す)
- 追証の下限の厳格化 (保有の下落を日経の 1.5倍とみなす等)。見送り (提案 2。ユーザー判断)
- 建て増し余地への条件 (指値・分割・Active 銘柄) の注記。見送り (提案 1)

## 実装

1. `scripts/margin_estimate.py`: 段と目標の純関数を足す
   - `target_step(emotion, fng, state)` → (step, 内訳) / `target_area(G, B, S, M, step)` → {target_rate, area_lower, area_upper, floor_capped, position}。P = S + M
   - `estimate` の戻り値に信用建玉の時価 `margin_value` (M = Σ 株数 × 終値。信用建玉の終値が欠けた証券会社はもともと推定しない) を足し、`combine` で G・B・S・M を合算して返す
2. 推定維持率の組み立て (今の `routes/portfolio.py` の `_margin_inputs` / `_build_margin_summary`) を、バッチからも呼べるよう `exposure_guide.py` 側へ移す (DB を読む関数。route はそれを呼ぶ)
3. `scripts/exposure_guide.py`: `evaluate_exposure` を新方式に置き換える。`apply_modifiers`・基準運用額・`settings --set-base-amount` CLI を外す。`EXPOSURE_DEFAULTS` は残すが使わない (DB 後方互換。`get_exposure_settings` も呼ばれなくなるだけ)
4. `scripts/portfolio_shelve.py`: `add_emotion_score` / `latest_emotion_score` (`KEY_EMOTION_PREFIX`)
5. route: `POST /portfolio/emotion`、`_build_exposure_summary` を新しい評価で組み立て、`_exposure_bar_geometry` を万円スケールに
6. テンプレート: `portfolio_list.html` のサマリー見出し・バー、感情スコアの入力 (`_margin_summary.html` と同じ「入れる」トグルの作り)
7. `webapp/action_queue.py`: 感情スコア未入力の行
8. `trade_review.py`: `exposure` 集計の切り替え
9. 文書: `doc/spec/推定維持率仕様.md` に「目標維持率と適正エリア」の節、`doc/decisions/` に「恐怖側で自動増枠しない (#362) を覆し、感情スコアと F&G の逆張りにする」判断記録、`doc/投資戦略.md` のレバ表をシートに合わせる、`doc/アーキテクチャ.md`・`doc/spec/市場ステート仕様.md`・`doc/spec/コマンド一覧.md` の運用比率の記述、`portfolio_shelve.py` の EXPOSURE_DEFAULTS コメント

## テスト (5本以内)
- `target_step`: parametrize (感情 × F&G 3区分 × 市場ステート、未入力、±3 で止まる)
- `target_area`: parametrize (増やす側は ΔB のまま、減らす側は M ÷ B で時価に直す、追証の下限で頭打ち、over/under/within)
- route: 感情スコアの保存とサマリー表示 (目標維持率・適正エリアの文言)
- action_queue: 5 営業日を過ぎたら未入力の行
- trade_review: 新旧の行が混在するときの exposure 集計

## 確認ポイント (完了報告で出す)
- 10/23 の実データでは、感情 0・F&G Extreme Fear → 段 −1 → 目標 70%。今の維持率 56.7% は多め側の端 (65%) より張っているので、**over (適正 1,920〜2,110万に対して約 200万多い) と出る**。基準運用額では 87% (調整局面のレンジ内) だった表示が逆になる
- 推定維持率の基準値が古いと、適正エリアもずれる (保証金率の入れ直しで戻る)
