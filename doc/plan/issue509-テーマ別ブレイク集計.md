# #509 Phase 1: テーマ別のブレイク集計を /market に出す

issue: #509 (2026-Q4)。この計画は Phase 1 だけを扱う。

## なぜ今やるか (書き直し)

**既に調べた銘柄がテーマごと動いたときに気づけるようにする**。9/15〜10/9 のセキュリティでは、2準・1保・3監の6銘柄がまとまって新高値を付けていたが、どこにも出ていなかった。

issue 本文の「発掘が SNS 発で、宣言なしの取引が赤字」は、Phase 1 の理由にしない。赤字の原因は衝動的な短期売買で、発掘元を替えても減らないため。未フォロー銘柄は最小限だけ出し、そこから監視に入れた銘柄の成績を月次の振り返りで拾えるようにする (効き目を測るための入口)。

### 判断記録 (`doc/decisions/2026-10-25-テーマ別ブレイクは株探テーマの本日リストを数える.md`)

- 2026-05-29 は、業態テーマ (手動分類) で RSライン新高値をグループ集計する案を「独自の breadth 指標になる」として採らなかった
- 今回は株探テーマ (市場の自動分類) で、日次バッチが既に作っている本日リスト (新高値・出来高急増・PTS) の銘柄数を数えるだけ。新しい指標の計算も、DB への書き込みも無い
- 使うのは銘柄をテーマ単位で見つける入口としてで、スコア・ランキング・評価台帳には入れない
- 見直し条件: 四半期末の仕様レビューで、使っていない、または既に調べた銘柄の動きに気づけた例が無ければ外す

## 作るもの

### 1. 集計 (`scripts/theme_breakout.py`、新規)

純関数とファイル読み込みを分ける。

- `load_result_csv(path)`: 日次レポート CSV を**見出しの名前で**読む (列の並びは 2026-03-13 に変わっている)。【本日銘柄】【本日既出銘柄】の行だけを返す。1行は `code_s`・銘柄名・種類・初出か・業績スコア・テーマ (リスト)・前日比・概要・ニュース1の見出し
  - コード・銘柄名・ニュースのセルは `=HYPERLINK(...)` の式なので、表示用の文字列を取り出す
- `recent_result_csvs(n=21)`: `shintakane_result_data/` と `history/` から `shintakane_result_YYMMDD.csv` を集め、日付の新しい順に n 件 (30日で history/ に移るため、両方を見る)
- `build_breakout(days, managed)`: 純関数。`days` は日付昇順の `[(date, rows)]`、`managed` は `{code_s: status}`
  - 最新日のテーマごとの該当数と、その前の最大 20 日の平均を比べ、条件を満たすテーマを残す (前日までの日数が 20 に満たなければ、ある分で平均する)
  - 該当数の多い順に、重複テーマを畳む → 先頭 8 行。9 行目以降は件数だけ返す
  - 1行: テーマ名・別名・該当数と内訳 (高 / 出 / P)・平常の平均・前20日の日ごとの該当数・管理対象・未フォロー銘柄・ほかの銘柄数
  - 管理対象: 1保 → 2準 → 3監 の順。各銘柄に、直近20営業日 (最新日を含む) で本日リストに載った日数を付ける
  - 未フォロー: 上の未決 8 のとおり。同じ銘柄が複数の行に出るときは、先の行だけに出す
- `load_for_display()`: 上の2つを読んで `build_breakout` を呼ぶ。管理対象は `portfolio_shelve.list_records()` (除外済みは含まない)。CSV が無ければ `None`

定数 (モジュール先頭): `MIN_COUNT = 5`、`RATIO = 2.5`、`WINDOW = 20`、`MERGE_OVERLAP = 0.6`、`MAX_ROWS = 8`、`MAX_UNFOLLOWED_PER_THEME = 2`

### 2. 表示 (/market)

- `routes/market.py` の `market_page()` で `theme_breakout.load_for_display()` を呼ぶ。例外は `log_warning` して `None` (この欄だけ省く。/market を 500 にしない)
- `market.html` の、市場データ (市場 → テーマランク) の直後、テーマニュース調査の前に `<details>` で1節を置く。見出しは「テーマ別のブレイク (日次レポート YYYY-MM-DD)」
  - 0行の日は「該当なし」
  - 1行 (テーマ):
    - テーマ名 (別名は小さく)
    - 該当数と内訳 (例: `24 銘柄 (高 20 / 出 3 / P 1)`、平常 1.1)
    - ツールチップに前20営業日の日ごとの該当数 (広がり方を見るため。条件を満たした日数を数えるには40日分読む必要があるので、そうしない)
  - 管理対象: ステータスのバッジ + 銘柄名を `/stock/<code_s>` にリンクし、掲載日数を添える
  - 未フォロー: 銘柄名だけ出す。ツールチップ (`title`) に種類・前日比・業績スコア・概要・ニュース1 を入れる。横に小さな「監視に追加」ボタンを置き、`/portfolio/add` に `code_s`・`reason` (発掘元の書式)・`return_to=market` を送る。管理対象・未フォローに出なかった銘柄は「ほか N 銘柄」とだけ出す
- `routes/portfolio.py` の `_redirect_with_return_query()` に `return_to=market` を1分岐足し、追加後に /market へ戻す (`return_to=detail` と同じ形)

### 3. 月次の振り返りで発掘元を拾う (`scripts/trade_review.py`)

- `_load_inputs()` で、action_log のうち reason が `発掘元:日次レポート` で始まるものを銘柄ごとに集める
- `trades.opened` / `trades.closed` の各行に `discovery` を足す: 建てた日以前の最後の発掘元ログの `{"theme", "date"}`、無ければ `null`
- `/trade-review` のスキルには、件数が出てから節を足す (今回は JSON に載せるだけ)。`attach_action_notes` は 3監への追加ログを捨てるので、そこには混ぜない

## やらないこと

## テスト (4本)

1. `build_breakout` が 2026-09-15 と 10-06 にセキュリティを該当させる (parametrize)。入力は運用機の 8/17〜10/6 の CSV から、テーマ列にセキュリティを含む行だけを `コード,銘柄名,種類,業績スコア,テーマ` と節の行に絞った fixture (`tests/fixtures/shintakane_result_509/`)
2. `build_breakout` の並びと絞り込み (小さな合成データ1つで): 重複テーマが6割で畳まれる、8行の上限、管理対象が 1保→2準→3監 の順、未フォローは初出かつ「高」だけで1テーマ2銘柄まで
3. /market が CSV 無し・壊れた CSV でも 200 を返す (parametrize)
4. `trade_review` の `discovery`: 建てた日より前の発掘元ログが付き、後のログは付かない

`theme_breakout.py` は testing.md の対応表に足す。`webapp/routes/` と `trade_review.py` は既存の対応表のテストも回す。
