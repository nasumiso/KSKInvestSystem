## 1. 保存失敗を見えるようにする (U4)

**対象の保存経路** (失敗が無言のもの)

- `static/app.js` `submitFormAsync` (詳細画面の IR コメント・メモ・四季報の自動保存)
- `static/app.js` のもう1つの POST 経路 (363行付近、決算エディタ)
- `templates/trade_history.html` の振り返りメモ
- `templates/detail.html` の fetch 8 か所は、着手時に1つずつ読み、失敗が無言のものだけ対象にする

**仕様**

- 保存に失敗したら (HTTP 失敗・通信失敗のどちらも)、編集した欄のそばに「保存できませんでした」と再試行の操作を出す。入力した文は消さない。未保存の印 (`dirty`) も残す
- 成功したときだけ「保存済み」を短く出す (サーバーの成功応答を受けた後)
- 保存中にさらに書き足した場合、先に送った分の成功で「保存済み」にしない (送った時点の値と今の値が同じときだけ保存済みにする)
- 既存の保存キューの直列化はそのまま
- 未保存の入力がある・保存の順番待ちがある・保存の通信中・失敗した欄が残っている、のいずれかの状態でページを離れようとしたら、ブラウザ標準の離脱確認を出す。自動保存はフォーカスを外した瞬間に送るので、欄を書いてすぐナビのリンクを押すと通信が途中で切れて内容が失われうる (今は無言)
- 表示は共通の小さな関数1つにまとめ、3つの経路から呼ぶ

**やらないこと**

- Esc の挙動変更。保存状態の表示を先に入れてから、ステップ 1b で行う
- `portfolio_list.html` の alert 表示の作り替え (すでに失敗が見える)
- サーバー側の変更

**検証**

- 開発用コピーの WebApp で、保存先のルートを一時的に 500 にする/WebApp を止める、の2通りで失敗を起こし、「対策前は無言 → 対策後は失敗表示・入力が残る・再試行で保存できる」を対で確かめる
- 成功時に DB の値が変わっていること、保存中の追記で誤って保存済みにならないこと
- 保存の応答を遅らせた状態 (開発用コピーのルートに一時的な待ちを入れる) で別ページへ移ろうとし、離脱確認が出ること。対策前は確認なしで遷移し、値が保存されないことも対で確かめる
- JS のみの変更なので pytest の追加はしない (テスト方針: テンプレート・JS はブラウザ確認)

## 1b. キーボード操作をそろえる (U4、#439 の仕様判断 4 の決着)

ユーザー決定 (2026-10-03): 自分のシステム全体でキー操作をそろえる。ステップ1 (保存状態の表示) が入ってから行う。

| キー | 挙動 |
|---|---|
| Esc | フォーカス中の欄で、最後に送信した後に書いた分を取り消して編集を抜ける (今は「フォーカスを外して保存」) |
| Ctrl+Enter / Cmd+Enter | 編集を終えて保存する |
| Enter | 複数行の欄では改行。1行の入力欄では確定して保存 |
| フォーカスを外す | 今までどおり自動保存 (スマホでは主な保存手段) |

- **日本語入力の変換中の Esc・Enter には反応しない** (`event.isComposing`)。変換の取り消し・確定であって、編集全体の取り消し・確定ではない
- Esc が取り消すのは**まだ送っていない編集だけ**。戻す先は「その欄で最後に送信した値」(送信がまだなら画面を開いたときの値)。一度フォーカスを外して送信済み・順番待ち・通信中になった変更は Esc では取り消さない (画面だけ戻すと、後から届いた保存で DB と食い違う)。送信済みの変更を戻したいときは、書き直して保存する
- Esc で抜けるときは保存を送らない (フォーカスが外れても自動保存を発火させない)
- Esc で取り消した直後、欄のそばに「取り消しました・元に戻す」を数秒出す。押すと取り消す前の文に戻る (長いメモを誤って消す事故への備え)
- 対象: 詳細画面のメモ・IR コメント・四季報、決算エディタ (Esc は「取り消して閉じる」になる)、売買履歴の振り返りメモ (今は Esc に反応しない)
- 対象外: 選んだ瞬間に保存される選択欄 (戦略など)
- `portfolio_list.html` と `portfolio_charts.html` のインライン編集は、もともと Esc 取消・Enter 確定・Ctrl/Cmd+Enter 確定 (複数行) だった。一覧側に変換中の無反応だけ足した
- 同じフォームの別の欄に未送信の編集が残っているときは、Esc で抜けた後にそちらは通常どおり自動保存される (Esc が取り消すのはフォーカス中の欄だけ)
- 四季報の順次更新は自動保存ではなく銘柄切替時に保存するので、Esc はフォーカスを外すだけ (従来どおり)
- 検証: 実画面で、変換中の Esc で文が消えないこと、未送信の編集を Esc した後に DB の値が変わっていないこと、送信済みの変更は Esc しても画面と DB が一致したままであること、「元に戻す」で文が戻ること、Ctrl+Enter と Cmd+Enter で保存されること

## 2. 検索条件の不整合を直す (U1)

**今の挙動**: ナビの検索 (`q`) で入ると、検索画面のコード欄・キーワード欄を変えても結果が変わらない (`q` が hidden で残り、`q` があると `code_s`・`keyword` を見ない)。

**仕様**

- `q` を hidden ではなく、見える入力欄 (「コード・銘柄名・メモ」) として出す。消せば `q` なしの検索になる
- `q` があるときも、コード欄・キーワード欄・評価を**すべて AND で**適用する
- 「条件をクリア」リンクを置く
- 変えないもの: 全角→半角の正規化、1件ヒット時の詳細への直行、コード形式で 0 件のときの「この銘柄を追加」、スニペット表示

**テスト**: `tests/test_webapp_routes.py` に parametrize で1本 (`q` + コード欄で絞れる / `q` + キーワードで絞れる / `q` だけなら従来どおり / 1件なら詳細へ)。

## 3. 売買履歴の文字色・選択中タブ (U3)

- 白背景の上にある薄い文字色 (`#ddd`・`#aaa`・`#9ef0aa`・`#f0a0a0` 等) を、判読できる濃さに替える。正は緑・負は赤の区別と符号は保つ
- 暗い背景のバッジ (信用・現物・保有中など) の中の明るい文字はそのまま。31 か所を1つずつ背景と照らして判断する
- 選択中タブを文字色と下線で分かるようにする
- 損益の正負・主要数値の色は、テンプレート内の CSS クラス 2〜3 個にまとめる (同じ色を 31 か所に書かない)
- 計算・集計・表示項目は変えない。検証は実画面 (スクリーンショットの前後比較)
