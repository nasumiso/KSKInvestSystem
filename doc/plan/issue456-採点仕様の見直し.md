## 決めたこと

### 全体

- 立ち位置は spec の「役割」のとおり。総合点の定義 (現在価格からの中期投資魅力度) は変えない
- 配点 (code_rank の重み、台帳の 40/20/20/20) の根拠探しはしない。等しい重みで足すだけでも最適化した重みとほぼ同じ予測力が出る (Dawes 1979)。見るのは実効的な効き方 (分散) と軸どうしの重なり
- 台帳の採点ルールを直すのは、変更履歴がたまる前の今。2027-03 の前向き検証 (仕様レビュー_0927 Part 4-5) は、採点ルールの版が同じ期間でしか比べられない

### 台帳のステータス基準 (#542)

- 範囲: 台帳 = 深掘り候補 + 実保有 (`投資戦略.md` の層)。一次資料で調べた銘柄だけを載せ、監視の層は載せない
- Active: 仮説が生きていて、持っている / 入る準備ができている (買いルールの A を満たす)。Watch: 仮説はあるが確認待ち (`checkpoints` 必須)。Archive: 仮説崩れ・時間切れ・見送り (理由を `note` に書く)
- 保有ステータスとは独立のまま、制約だけ置く: 1保 ⇒ Active (大型高配当・短期イベント・短期底値リバは除く)、Active ⇒ 1保か2準、Active / Watch ⇒ ポートフォリオに登録
- 新規登録は thesis・risks・checkpoints 必須。上限 Active 20 / Watch 15。決算から14日を過ぎて未更新の Active、決算を2回またいだ Watch を知らせる
- Archive は消さずに残し、比較 (順位・一覧の既定・一括付け直し) から外す。消さないのは見送った銘柄のその後を追うため
- 外れたものは「今日のアクション」で知らせるだけで、Status は自動で変えない (変えるのは判断なので人が行う)。`RUBRIC_VERSION` は上げない (点数の付け方は変わらない)

### 台帳 Ver3 (#544)

- 4軸・100点の配点、Confidence は据え置き
- ファンダ: レンジ表の目安を下げ、ユニバースの中央が 28 前後になるようにする。36-40 最上位 (ユニバースで数銘柄) / 31-35 強い / 26-30 良好 / 21-25 不確実性高 / 16-20 テーマ・回復依存 / 15未満 オプション中心。内訳は据え置き
- 未織込: 「今わかっている数字 (会社予想・四季報予想) と、これから出る数字の差」と定義し直す。内訳は 上振れ余地 10 / 次の数字 5 / 再評価のきっかけ 5。株価の水準・PER・騰落・決算後の株価反応は見ない
- Valuation: 内訳は据え置き。成長率対比で使った成長率とその出どころを note に書く。システムの数値を渡すのは #486 で、Ver3 はその完成を待たない
- モメンタム: AI の採点から外す。`update_stock_rating` に momentum を渡したらエラーにする (黙って無視すると、ChatGPT が書いたつもりで反映されないことに気づけない)。説明文には「`get_stock_rating` でシステムのモメンタムを見られる」と書く
- 切り替えのときに非 Archive の銘柄を一括で付け直す。ChatGPT で、台帳の既存の記述と MCP のデータを元にした移行採点 (資料の読み直しはしない)。1チャット 10銘柄前後、更新理由は「Ver3 移行」。採点者を ChatGPT のままにするのは、採点者の違いが点数に混ざると前向き検証で切り分けられないため

### 台帳のモメンタムのシステム算出 (#543)

- 20点 = 個別の相対強度 10 (`momentum_pt` ÷ 10) + 業態テーマの勢い 10 (業態テーマの6ヶ月相対の順位を、1位=10・最下位=0 で線形に。テーマが2つなら平均)
- テーマ側に RSスコア平均を使わないのは、個別の要素と同じ物差しを2回使うことになるため (構成3〜5銘柄のテーマでは、その銘柄自身が平均の大半を占める)
- 欠けた要素は中央の5点で埋め、「欠」の印を付ける (2026-11-01 時点で 418A は価格データ無し、3968 は業態テーマ無し)
- 正本の JSON には保存せず、読み出すたびに計算する。HTML と Drive への出力は日次バッチの最後に作り直し、Drive に出す JSON にだけ算出値を埋め込む
- `update_stock_rating` で更新したとき、その時点のモメンタム (合計と内訳) をシステムが変更履歴に残す。`rs_rank_log` は250日分しか残らず、置き場所も揮発DBなので、前向き検証の材料にはしない
- 決算後の反応・出来高は点数に入れず参考表示にとどめる。組み込みは #545 で検討する (決算後の反応は WebApp の詳細ページを開いたときにしか埋まらず、最新四半期まであるのは52銘柄中28)

### code_rank (#546)

- 「ファンダメンタル」列の表示名を「テーマ」に変える。内部のキー・重み・閾値は変えない
- 重み・閾値の調整は、前向き計測 (code_rank 上位銘柄のその後) を作ってから。この計測は #456 の外で別 issue にする (未起票)

## 却下した案

| 案 | 却下した理由 |
|---|---|
| 台帳のモメンタムを総合点から外す | 上昇に対して Valuation・未織込の減点だけが効き、強い銘柄ほど点が下がる。早売りの癖を後押しする |
| 台帳の Valuation を code_rank に吸収する | 成長率対比は「どの成長率を使うか」が判断で、一律には出せない |
| code_rank の指標をグロース向けの割安度に作り直す | 全銘柄に一律で使える物差しが無い。割安さの判断は台帳に任せる |
| 一括付け直しを決算更新のたびに順次行う | Ver2 と Ver3 が数ヶ月混在し、総合点を比べられない |
| 一括付け直しを Claude Code (同じ MCP) で行う | 採点者が変わると前向き検証で切り分けられない |

保留: ファンダの足切り (例: 25未満は Archive) として使う案。#542 のステータス基準と合わせて考える。
