# issue #578: ブを本来のブレイクアウトの定義に寄せる

## 背景

ブ (`breakout`) はミネルヴィニ・オニールのブレイクアウトを日々の値動きから検知する意図のシグナルだが、今の条件は「出来高が30日平均の1.5倍以上 (またはストップ高) で、前日より高く引け、10日MA からの乖離が5%以内」で、**価格の上抜けを見ていない**。トレンドは、週足の7条件がすべて不合格 (ステージ4) の銘柄を除くだけ。今日のアクションにブが1日40件以上出て埋もれる。

#340 (VCP・ピボット価格・`[BP]`・カップ・ウィズ・ハンドル) も同じ目的の issue なので、合わせて検証し、効いたものだけをここに取り込む。#340 は作らずに閉じる。

## 検証 (2026-11-11〜12)

過去の日足に今の判定を当てて再現し、その日の終値で買って30日以内に +10% と −7% のどちらに先に届くかを数えた。表の数字は「+10% に先に届いた割合 − −7% に先に届いた割合」の、**基準 (何もない日) との差**。プラスなら基準より有利。

- 対象: A = 管理中の約320銘柄 (保有・準保有・監視。今選んでいる銘柄なので良い側に偏る)、B = それ以外から無作為に選んだ800銘柄のうち売買代金の中央値が3千万円以上の約700
- 期間: 5年。前半 = 〜2024/10、後半 = 2024/11〜
- 連日のシグナルは最初の1件だけ数えた。ステージ2と52週の範囲は本番の週足の条件を日足に換算した (30週MA ≒ 150日、40週MA ≒ 200日)

| | B 前半 | B 後半 | A 前半 | A 後半 |
|---|---|---|---|---|
| 今のブ | −1.1 | −1.6 | +2.0 | +2.3 |
| 本来のブ (20日高値抜け + ステージ2 + 52週) | −4.6 | +6.7 | +3.9 | +4.9 |
| 本来のブ + 出来高2倍以上 | −0.6 | +7.5 | +8.1 | +8.3 |
| 本来のブ + 直前10日の値幅 10%未満 + 出来高2倍以上 | +0.7 | +11.1 | +10.9 | +14.5 |
| 本来のブで直前10日の値幅 12%以上 | −7.0 | −10.5 | −4.2 | −0.6 |
| 週ブ 全体 | −2.4 | +2.8 | +4.2 | +2.6 |
| 週ブだけ (直近5日に今のブなし) | −3.5 | −14.0 | +6.3 | +11.2 |

読み取れること:

- **今のブには、どの切り口でも優位性が無い**
- **本来のブは今のブより良いが、時期と銘柄に左右される**。無作為の銘柄の前半は基準より悪い。単独の買いシグナルではなく、調べ済みの銘柄が動いた日に気づくための印として扱う
- **直前の値動きが締まっていて出来高が2倍以上のブは、4区分すべてで本来のブより良い**。値幅は狭いほど良い (8% > 10% > 12% > 15%)。値幅が広いブは4区分すべてでマイナス
- 高値を見る日数は 20〜50日でほぼ同じ (管理中の2年分での比較)。20日なら今の日足の取得 (約60日) のまま足りる
- **週ブは一貫しない**。「ブが出ずに週ブだけ」は管理中の銘柄では良いが、無作為の銘柄では悪い

#340 の要素 (本来のブを特徴で分けた結果):

| 要素 | 結果 |
|---|---|
| VCP らしい形 (収縮が縮小) | 管理中と無作為、前半と後半で符号が変わる |
| カップ・ウィズ・ハンドルらしい形 | 該当が51〜99件と少なく、管理中と無作為で逆 |
| ベースの長さ・深さ、何日ぶりの高値か | 一貫した傾向なし |
| ピボットから5%以内 (高値追いの規律) | 支持されない。10%以上伸びた日のほうが良い |
| 出来高の枯れ | 3区分で改善、無作為の前半で悪化 |
| 引けの位置 | 逆の結果 (下半分で引けた日のほうが良い) |

限界: VCP・CWH は簡易な判定での結果。2026-11-11 に管理中の2年分だけで測ったときは本来のブの差が +8 前後に見えたが、対象と期間を変えると上の表まで縮んだ (issue の本文の表は古い数字)。検証スクリプトは残さない。

## 仕様

### ブ

今の検知条件はそのままにし、**表示の条件**を3つ足す。3つとも満たすものだけを「ブ」として出す。

1. **高値の上抜け**: 発生日の終値が、直前20営業日の終値の高値を上回る (`BREAKOUT_PIVOT_DAYS = 20`)。直前が20日に満たない銘柄は満たさない扱い
2. **ステージ2**: 週足トレンドテンプレートの中核3条件 (`pr>ma30,40` / `ma30>ma40` / `ma40Up`) をすべて通過。ポの判定と同じ集合 (`_POCKET_PIVOT_TREND_CORE`) を使う
3. **52週の範囲**: トレンドテンプレートの `high(low)52` を通過 (52週高値の25%以内、52週安値の1.3倍以上)

ステージ4 (全条件不合格) と週足データ欠損 (trend_template が None) で出さないのは今のまま。2 と 3 は、ポと同じく**今の**トレンドテンプレートで判定する (発生日時点ではない。シグナルは直近10日以内なので差は小さい)。

### ブ+ (強いブ)

ブのうち、次の2つを満たすものを「ブ+」とする。

- **直前が締まっている**: 発生日の前10営業日の値幅 (高値の最大 − 安値の最小) が、前日終値の10%未満 (`BREAKOUT_TIGHT_RANGE_PCT = 10`)
- **出来高が30日平均の2倍以上** (今の強さの区分で「中」以上)

ストップ高で出来高が細った日はブ+にならない。

### 週ブ

変えない。検証で一貫した結果が出なかったので、「ブが出ていない銘柄にだけ出す」案は採らない。12月末の仕様レビューで、実際に出たシグナルのその後を見て扱いを決める。

### 詳細チャートの印

| 印 | 変更後 |
|---|---|
| 橙の◆ (塗り) | ブ (最新1件)。ツールチップは、ブ+なら「ブ+」と直前10日の値幅を出す |
| 橙の◇ (中抜き) | 今の「高値追い圏・対象外」に加え、3条件のどれかを満たさなかったブ。ツールチップに外れた理由を出す: 「高値未更新」「ステージ2でない」「52週の範囲外」(複数なら「・」でつなぐ)。サイズは出来高の強さ |
| 紫の◆ (週ブ)、緑の▲ (ポ) | 変えない |

中抜きは、今の高値追い圏と合わせて直近3件まで。

### 一覧のシグナル列

- `make_signal` の文字列は、条件を満たすものだけ `[ブ]`、ブ+は `[ブ+]`
- 記号は「ブ」「ブ+」。ツールチップは、ブ+なら直前10日の値幅を添える

### 今日のアクション

- `extract_signals` を通しているので、ブは新しい条件で自動的に絞られる
- 11/11 に入れた「ブ(弱) は出さない」と「週ブを含む銘柄を先に並べる」をやめる。ブはすべて出し、**ブ+ を先に**、その中で新しい順に並べる
- 銘柄名の後ろとポップアップの種類は「ブ+」「ブ」「週ブ」。監視の内訳は「ブ+2・ブ7・週ブ5」のように出す

## 実装

### 1. `price.py` (検知)

- ブレイクの走査で、高値の上抜けと直前10日の値幅を求めて保存する。保存形式を `"MM/DD,per"` → `"MM/DD,per,H,R"` にする (H = 1: 上抜け / 0: していない、R = 直前10日の値幅 %、小数1桁。直前が10日に満たなければ R は付けない)。既存の読み手は先頭2要素しか読まないので互換
- `breakout_extended` (`"MM/DD,kairi,per"`) と `volume_dryup_breakout` は変えない
- 日足の取得期間は変えない (走査10日 + 高値20日 = 30日で、今の約60日に収まる)

### 2. `make_stock_db.py` (解釈)

閾値の判定は解釈層に置く (条件を変えても再取得が要らない)。

- `_breakout_reject_reasons(stock, sig) -> List[str]`: ブ1件が表示条件から外れる理由を返す (空なら表示してよい)。3要素目が無い旧データは高値の条件を問わない (次の価格更新で入れ替わる)
- `_is_strong_breakout(sig) -> bool`: per ≥ 100 かつ R < 10。R が無ければ False
- `extract_signals`:
  - ブ: `breakout` を新しい順に見て、理由が空の最初の1件を出す。ブ+なら `strong=True`、R があれば `range` を付ける
  - `include_extended=True` のとき、理由がある `breakout` の項目を `kind="ブ"`、`extended=True`、`reject="高値未更新・…"`、`num=per`、`extended_per=per` にする。これと `breakout_extended` (高値追い圏) の項目を**1つのリストにまとめて発生日の新しい順に並べ、先頭3件だけ**を返す (別々に3件ずつ足さない)
- `make_signal` の `[ブ]` も同じ関数で判定する

### 3. `webapp/helpers.py`

- 一覧の記号とツールチップ: `strong` なら「ブ+」と値幅
- `_resolve_signal_markers`: `reject` `strong` `range` を marker に引き継ぐ
- 中抜きの印のツールチップ: `reject` があれば `ブ(ex/強) 11/10 出来高+150% 高値未更新・対象外`、無ければ今の `乖離+N% 高値追い圏・対象外`

### 4. `webapp/action_queue.py`

- `BREAKOUT_HIDDEN_STRENGTHS` と週ブ優先の並びを消す
- 銘柄ごとの集約 (`found[status][code_s]["kinds"]`) に入れる種類を、`extract_signals` の項目が `kind="ブ"` かつ `strong` なら「ブ+」、それ以外は kind のままにする。`extract_signals` が返すブは銘柄ごとに最新1件なので、1銘柄に「ブ+」と「ブ」が同時に入ることはない (週ブとは同時に入りうる)
- 表示の順と内訳の順は `BREAKOUT_KINDS = ("ブ+", "ブ", "週ブ")`。銘柄の並びは「種類にブ+を含む銘柄が先 → 発生日の新しい順 → コード順」

### 5. 文書

- `doc/システム概要.md` のブレイクアウトの説明、`doc/アーキテクチャ.md` の今日のアクションの節、`doc/用語集と不変条件.md` に「ブ / ブ+ / 週ブ」の定義を1行
- `doc/decisions/` に判断記録 (検証の表と限界、採らなかった案: VCP・CWH の検出器と `[BP]`、ピボットのゾーン表示、出来高の強さだけで絞る、週ブをブの補完に絞る、底値圏の出来高急増を別シグナルにする)
- #340 は、判断記録へのリンクを書いて閉じる
- この計画書は実装の PR で削除する

### 6. テスト (5本以内、parametrize で集約)

- `test_price.py`: 高値の上抜けの有無と直前の値幅で、3・4要素目が決まる (既存のブレイクのテストの期待値も直す)
- `test_make_stock_db.py`: `extract_signals` のブ (3条件すべて / 高値未更新 / ステージ2でない / 52週の範囲外 / 旧2要素データ / ブ+) と、`include_extended` での理由つき項目
- `test_webapp_helpers.py`: 中抜きの印のツールチップ (理由つき) と、ブ+ の記号
- `test_action_queue.py`: ブ+ を先にした並びと種類の表示

## 反映

- 保存形式が変わるので、反映後に価格を更新した銘柄から新しい判定になる。更新前の銘柄 (2要素) は高値の条件だけ問わずに出て、ブ+にはならない。管理中の銘柄は日次バッチで毎日更新されるので、翌日には揃う
- 反映後、運用機の実データで今日のアクションの件数 (変更前 → 変更後) と、詳細チャートの塗り・中抜きの印を確かめる
- 12月末の仕様レビューで、反映後に出たブ・ブ+・週ブのその後の値動きを確かめる

## 対象外

- ベースの形 (VCP、カップ・ウィズ・ハンドル) の検出、ピボット価格の保存とゾーン表示、`[BP]`: 検証で一貫した効果が出なかった
- 50日平均の出来高への変更: 30日平均で十分近く、日足の取得を延ばす必要が出る
- 過去のシグナルの保持 (`signal_history_retention.md`)
