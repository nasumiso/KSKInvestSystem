# issue #578: ブ・週ブを本来のブレイクアウトの定義に寄せる

## 背景

ブ (`breakout`) はミネルヴィニ・オニールのブレイクアウトを日々の値動きから検知する意図のシグナルだが、今の条件は「出来高が30日平均の1.5倍以上 (またはストップ高) で、前日より高く引け、10日MA からの乖離が5%以内」で、**価格の上抜けを見ていない**。トレンドは、週足の7条件がすべて不合格 (ステージ4) の銘柄を除くだけ。今日のアクションにブが1日40件以上出て埋もれる。

## 検証 (2026-11-11)

管理中の325銘柄 (保有・準保有・監視) の日足で、今のルールを過去約2年分再現した。「差」は、その日の終値で買って30日以内に +10% に先に届いた割合から −7% に先に届いた割合を引いたもの。ステージ2と52週の範囲は本番の週足の条件を日足に換算した (30週MA ≒ 150日、40週MA ≒ 200日)。

- 高値を見る日数は 20〜50日でほぼ同じ。20日なら今の日足の取得 (約60日) のまま足りる
- 週ブの8割はブと重なり、その場合は優位性が無い。良かったのは「ブが出ずに週ブだけ」の形。ステージ2・52週で絞っても変わらない (標本が少ない)

検証スクリプトは残さない (再現する場合は、yfinance の3年分の日足に今の判定を当てる)。

## 仕様

### ブ

今の検知条件はそのままにし、**表示の条件**を3つ足す。3つとも満たすものだけを「ブ」として出す。

1. **高値の上抜け**: 発生日の終値が、直前20営業日の終値の高値を上回る (`BREAKOUT_PIVOT_DAYS = 20`)。直前が20日に満たない銘柄は満たさない扱い
2. **ステージ2**: 週足トレンドテンプレートの中核3条件 (`pr>ma30,40` / `ma30>ma40` / `ma40Up`) をすべて通過。ポの判定と同じ集合 (`_POCKET_PIVOT_TREND_CORE`) を使う
3. **52週の範囲**: トレンドテンプレートの `high(low)52` を通過 (52週高値の25%以内、52週安値の1.3倍以上)

ステージ4 (全条件不合格) と週足データ欠損 (trend_template が None) で出さないのは今のまま。2 と 3 は、ポと同じく**今の**トレンドテンプレートで判定する (発生日時点ではない。シグナルは直近10日以内なので差は小さい)。

### 週ブ

検知条件 (乾→増→抜) は変えない。**直近にブ (今の検知条件のブ。上の3条件を問わない) が出ていない銘柄にだけ**出す。

- 「直近」= 週ブの発生日とその前4営業日。日付の差が暦日で0〜6日のブがあれば出さない (4営業日は週末をまたいで最大6暦日。祝日は考慮しない)
- ステージ2・52週の条件は足さない (検証で差が出なかった)。ステージ4で出さないのは今のまま
- 制約: `breakout` は直近10営業日の走査分しか持たないので、10営業日近く前の週ブでは、その前のブを見落とすことがある。今日のアクション (発生から3営業日) では起きない

### 詳細チャートの印

| 印 | 変更後 |
|---|---|
| 橙の◆ (塗り) | 上の3条件を満たすブ (最新1件) |
| 橙の◇ (中抜き) | 今の「高値追い圏・対象外」に加え、3条件のどれかを満たさなかったブ。ツールチップに外れた理由を出す: 「高値未更新」「ステージ2でない」「52週の範囲外」(複数なら「・」でつなぐ)。サイズは出来高の強さ |
| 紫の◆ | 補完の条件を満たす週ブ。満たさないものは出さない |

中抜きは、今の高値追い圏と合わせて直近3件まで。

- 一覧のシグナル列 (`make_signal` の `[ブ]` `[週ブ]`、`extract_signals` の記号とツールチップ) は、新しい条件を満たすものだけ出す

## 実装

### 1. `price.py` (検知)

- ブレイクの走査で、高値の上抜けを判定して保存する。保存形式を `"MM/DD,per"` → `"MM/DD,per,H"` (H = 1: 上抜け / 0: していない) にする。既存の読み手は先頭2要素しか読まないので互換
- `breakout_extended` (`"MM/DD,kairi,per"`) と `volume_dryup_breakout` は変えない
- 日足の取得期間は変えない (走査10日 + 高値20日 = 30日で、今の約60日に収まる)

### 2. `make_stock_db.py` (解釈)

- `_breakout_reject_reasons(stock, sig) -> List[str]`: ブ1件が表示条件から外れる理由を返す (空なら表示してよい)。3要素目が無い旧データは高値の条件を問わない (次の価格更新で入れ替わる)
- `_weekly_breakout_displayable(stock, sig) -> bool`: 週ブ1件の補完条件
- `extract_signals`:
  - ブ: `breakout` を新しい順に見て、理由が空の最初の1件を出す
  - 週ブ: 最新1件が補完条件を満たせば出す
  - `include_extended=True` のとき、理由がある `breakout` の項目を `kind="ブ"`、`extended=True`、`reject="高値未更新・…"`、`num=per`、`extended_per=per` で足す (今の高値追い圏の項目と合わせて、新しい順に3件まで)
- `make_signal` の `[ブ]` `[週ブ]` も同じ2つの関数で判定する

### 3. `webapp/helpers.py` (チャートの印)

- `_resolve_signal_markers`: `reject` を marker に引き継ぐ
- 中抜きの印のツールチップ: `reject` があれば `ブ(ex/強) 11/10 出来高+150% 高値未更新・対象外`、無ければ今の `乖離+N% 高値追い圏・対象外`

### 4. `webapp/action_queue.py`

- `_breakout_items` の並びを新しい順 (同日はコード順) に戻す

### 5. 文書

- `doc/システム概要.md` のブレイクアウトの説明、`doc/アーキテクチャ.md` の今日のアクションの節、`doc/用語集と不変条件.md` に「ブ / 週ブ」の定義を1行
- `doc/decisions/` に判断記録 (検証の表、採らなかった案: 出来高の強さで絞る / 週ブをやめる / 週ブにもステージ2の条件 / 底値圏の出来高急増を別シグナルにする)
- この計画書は実装の PR で削除する

### 6. テスト (5本以内、parametrize で集約)

- `test_price.py`: 高値の上抜けの有無で3要素目が 1 / 0 になる (既存のブレイクのテストの期待値も3要素に直す)
- `test_make_stock_db.py`: `extract_signals` のブ (3条件すべて / 高値未更新 / ステージ2でない / 52週の範囲外 / 旧2要素データ) と、`include_extended` での理由つき項目
- `test_make_stock_db.py`: 週ブ (直近にブなし / 6暦日以内にブあり / 7暦日前のブ)
- `test_webapp_helpers.py`: 中抜きの印のツールチップ (理由つき)
- `test_action_queue.py`: 並びを新しい順に戻した期待値

## 反映

- 保存形式が変わるので、反映後に価格を更新した銘柄から新しい判定になる。更新前の銘柄 (2要素) は高値の条件だけ問わずに出る。管理中の銘柄は日次バッチで毎日更新されるので、翌日には揃う
- 反映後、運用機の実データで今日のアクションの件数 (変更前 → 変更後) と、詳細チャートの塗り・中抜きの印を確かめる

## 対象外

- ベースの形 (VCP、カップ・ウィズ・ハンドル) や値幅の締まりの判定: 今回の検証では効果がはっきりしない
- 引けの位置の条件: 検証で逆の結果 (下半分で引けた日のほうが良い)
- 50日平均の出来高への変更: 30日平均で十分近く、日足の取得を延ばす必要が出る
- 過去のシグナルの保持 (`signal_history_retention.md`)
