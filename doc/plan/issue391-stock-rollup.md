## 2. 実データが起票時から倍増している

#390 マネックス取込の反映により、issue 本文およびコメントの実測値はすべて古い。**再実測した値:**

| | issue 本文 | issue コメント | **現在** |
|---|---|---|---|
| エピソード数 | 205 | 202 | **410** |
| 銘柄数 | 84 | 83 | **158** |
| 実現損益 | +3,132,356円 | +3,017,649円 | **+8,623,415円** |
| 期待値 | +3.668643% | +3.495532% | **+4.306878%** |
| 母数 (ep / 銘柄) | 154 / 69 | 153 / 69 | **342 / 145** |

### 2-1. 設計の核 (不変条件) は無傷

```
実現損益合計  エピソード単位 +8,623,415円 == 銘柄単位 +8,623,415円   ✅
期待値        エピソード単位 4.306878%   == 銘柄単位 4.306878%       ✅
```

金額加重ゆえグループ化に依存しないという issue の論証は、データが倍増しても厳密に成立する。**この不変条件をテストで固定する方針は変更なし。**

### 2-2. 勝率の説明を訂正する (issue との相違点)

issue は「**エピソード単位より勝率は下がりやすい**」と注釈に書くよう指定しているが、現データでは **51.75% → 53.10% と上がっている**。

負けラウンドを含む銘柄がトータルで1敗に畳まれる効果 (下げ要因) と、負けラウンドが勝ちラウンドに吸収されて銘柄トータルでは勝ちになる効果 (上げ要因) は**どちらも起こりうる**。データ次第でどちらにも振れるため、注釈は方向を断定しない文言にする:

> 銘柄単位: 同一銘柄の全エピソード (現物・信用・複数ラウンド) を1トレードとして集計。複数ラウンドが1件に畳まれるため勝率・ペイオフはエピソード単位と一致しません。実現損益と期待値はどちらの単位でも一致します。

### 2-3. `open_unrealized_partial` が立つ銘柄は現データに存在しない

`unrealized=None` のエピソードは現在 1件ある (`9252`、現物、保有中) が、`9252` は **closed 2本 + open 1本**で、その唯一の open エピソードが `None`。銘柄単位で見ると「一部だけ None」ではなく **全 open が None** に当たるため、issue 本文の定義では `open_unrealized=None` → 表示は `—` であり、**`*` は付かない**。

`open_unrealized_partial=True` になるのは「open が複数あり一部だけ `unrealized=None`」のケースで、**現データには該当銘柄がない**。

フラグの実装自体は issue 本文どおり行う (将来の両建て・部分的な価格欠損に備える) が、**検証は実データではなくユニットテスト側で担保する** (テスト1の parametrize に「open 2本のうち1本が None」のケースを含める)。

代わりに `9252` は別の検証に使う。この銘柄は含み損益が `—` でありながら **`open_realized` = +81,340円** を持つため、issue が設計した「含み損益列の title に `うち部分売り確定 +N円` を併記」がまさに効くケース。実データ確認はこちらで行う。

## 3. 実装内容

issue #391 の「実装方針」「テスト方針」「実装順序」をそのまま採用する。要点のみ再掲:

1. `webapp/helpers.py` に `build_stock_rollups(episodes)` を追加 (引数は `db_path` でなく `episodes`)。既存関数は無改変
2. テスト 1-3 を書いて通す — 数値を固定してから UI に進む。テスト1の parametrize には **「open 2本のうち1本が `unrealized=None`」= `open_unrealized_partial` が True になるケース**を必ず含める (実データに該当銘柄がないため、ここでしか担保できない)。「open 1本が None」= `open_unrealized is None` かつ `partial` は False、も併せて固定する
3. `routes/trade_history.py` に `stock_rollups` / `stock_summary` / `stock_priced_count` を追加。`stock_total_pl` は作らず `fill_total_pl` を使い回す
4. `trade_history.html`: エピソード行+明細行を `{% macro episode_rows(ep, uid) %}` に切り出し、サマリーもマクロ化。既存ブロックは `<div id="th-view-episode">` で包むだけでロジック無改変
5. セグメント2ボタン + `.th-stock-row` トグル + `localStorage['th-fill-view']`
6. テスト4 とブラウザ確認

`hold_days` は sum (通算保有日数)、サマリー下段のラベルは銘柄ビューでは「平均通算保有」。`qty_peak` は max。実現損益列はクローズ済みのみで `open_realized` は含み損益列の title に併記 — いずれも issue 本文どおり。
