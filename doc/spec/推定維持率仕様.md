# 推定維持率仕様

保有銘柄ページのサマリーに、楽天と SBI を合わせた**推定維持率**と、**追証 (20%) までの下落率**を出す (issue #527)。厳密な値ではなく概算。証券会社の保証金データは CSV で取れないので、ユーザーが入れる保証金率を基準値にし、そのあいだは残高 CSV の建玉と株価から差分で推定する。同じ推定から自己資本を出し、運用総額の**今週の目標の倍率**と**適正エリア**も出す (issue #593、末尾の節。#480 の目標の維持率を置き換えた)。

実装: `scripts/margin_estimate.py` (純粋関数)、`scripts/exposure_guide.py` (`build_margin_state` / `build_evaluation` / 日次ログ)、`scripts/webapp/routes/portfolio.py` (`save_margin_baseline` / `save_emotion_score`)、基準値の保存は `portfolio_shelve` の `margin_baseline:<証券会社>`、感情スコアは `emotion:<入力時刻>`。

## 入力

保有銘柄ページの「保証金率を入れる」で、証券会社ごとに1つ入れる (片方だけでもよい)。基準日は入力した日。

| 証券会社 | 画面 | 入れる項目 |
|---|---|---|
| 楽天 | iSPEED: 資産・照会 → 余力・保証金率 → 国内株式 / Web: 口座管理 → 余力詳細 | 「保証金率」(受入保証金合計 ÷ 建玉合計) |
| SBI | アプリ: 口座管理 → 余力／評価 → 保証金率タブ / Web: 信用建余力 → 右上の「リアル委託保証金率」 | 「委託保証金率」の値洗い基準 (実質保証金 ÷ 建代金合計) |

追証の判定用の値 (楽天の「本日の追証判定用」、SBI の「追加保証金基準保証金率」) は前営業日の建代金を基準にすることがあるので使わない。

**楽天は残高 CSV から自動で入る** (issue #605)。assetbalance(all) 版と信用建玉 CSV を一緒に取り込むと、取込日を基準日にして基準値を保存する (`"source": "csv"`。手で入れると上書きする)。

- 保証金率 = (国内株式信用保証金 + 預り金 + 0.8 × 代用の現物 + 評価損) ÷ 建玉合計
  - 楽天は預り金も受入保証金に入る
  - 評価損は、信用建玉 CSV の建玉ごとの「評価損益額」(諸経費を引いた値) の負の分
  - 現物の値と基準値の終値は、CSV の現在値を使う (現金と同じ時点にそろえる。19時の後を待たない)
- 2026-11-26 の CSV では **58.06%** で、画面は 58.13%。終値で評価損を出すと、諸経費 (約3万) の分だけ高い 58.51% になる
- 保存しないとき (取込完了の通知に理由を出す)
  - 信用建玉 CSV を一緒に取り込んでいない
  - (JP) 版で現金の行が無い
  - 現物に現在値の無い銘柄がある
  - 既存の基準値のほうが新しい日付
- 手入力の欄は残す。3回ほど画面の値と ±0.5pt で合ったら外す

手入力で保存できる条件 (満たさなければ理由を出して保存しない。入力値の分母と保存する建玉合計を同じ日にそろえるため):

- その証券会社の残高 CSV のソース (全口座) の取込日がすべて今日
- その証券会社の保有銘柄の終値が、直近の営業日のもの (日次バッチ後の入力が前提)
- その証券会社の現物と信用の両方の残高 CSV が取り込み済み
- 信用売建が無い・信用買建の建単価と終値が欠けていない

## 推定

証券会社ごとに、銘柄単位 (全口座を合算) で計算する。

- 建玉合計 B = 信用買建の Σ 株数 × 建単価 (残高 CSV の `avg_price`。同じ銘柄の複数建玉は株数の加重平均)
- 受入保証金 G = 基準値 + 信用建玉の評価損の変化 + 決済損益 + 代用の値動き
  - 評価損 = Σ min(0, 株数 × (終値 − 建単価))。**評価益は保証金に数えない** (SBI のヘルプが明記)
  - 決済損益 = 基準日より後の信用返済の約定 (fill) の損益。SBI は CSV の決済損益、楽天は (約定単価 − 建単価) × 株数 (往復行と同じ定義。諸経費は含まない)。決済損益が分かる銘柄は、基準日の評価損の控除を外して決済損益に置き換える
  - 決済損益が分からない銘柄 (約定履歴が未取込、楽天の当日の未確定 CSV で建単価が無い) は、建玉が減った分の損を基準日の値で残す (決済損益 ≒ 基準日の評価損とみなす)
  - 代用 = 0.8 × Σ [基準日から保有の株 × (終値 − 基準日の終値) + 増えた株 × (終値 − 取得単価)]
  - NISA 口座の現物は代用にならないので、代用にも下落率の現物時価にも数えない。運用総額 (適正エリアの比較対象) には数える
- 推定維持率 = G ÷ B。総合は Σ G ÷ Σ B
- 追証までの下落率(T) = 全保有が一律に x 下がったときの保証金率が T に届く x。T = 30 / 25 / 20%。建玉ごとに時価で評価損を出し直すので、評価益のある建玉は益が消えるまで保証金を減らさない (二分法で探す)
- 証券会社別の推定が 30% を下回れば注記する (追証は証券会社ごとの判定)

## 近似の限界

- 基準日以後の**入出金・金利・現物の売却代金・現引は追わない**。保証金率を入れ直すと戻る
- 決済損益は約定履歴 CSV を取り込んだ分だけ入る。楽天は諸経費を引かない
- 残高 CSV は銘柄単位の合算なので、基準日の前後で同じ銘柄の株が入れ替わっても区別できない
- 現物の全株が代用とは限らず、掛目は一律 0.8 (楽天の 2026-10-23 の実例は時価に対して約 0.76)
- 楽天が評価益を保証金に数えるかは公式の説明で確かめられていない
- 残高 CSV が古いと建玉合計が実態からずれる。基準値の入力時に CSV の取込日を確認し、表示にも日付を出す
- 保存のたびに、直前の基準値からの推定と実際に入れた値のずれを記録し、入力欄に出す

## 出さない条件

- 基準値が無い証券会社は計算しない。どちらも無ければ入力欄だけ出す
- 信用売建がある、信用建玉が無い、建単価が欠けた建玉がある証券会社は推定しない (欠けた建玉を落とすと維持率が高く出る)
- 基準日から株数が増えた現物で取得単価が欠けていれば、その証券会社は推定しない
- 信用建玉の終値が取れない証券会社は推定しない (建玉合計だけ増えて維持率が低く出るため)。終値が取れない現物は計算から除き、件数をツールチップに出す

## 今週の目標の倍率と適正エリア (issue #593)

正本は [投資戦略.md](../投資戦略.md) の「資金管理で守る3つ」「張りたい量」「張れる量」、判断は [2026-11-26 の判断記録](../decisions/2026-11-26-運用総額はふだん一定で口座の上限をかけ信用の底で買い向かう.md)。決め方は #594 の検証 (`scripts/money_rule_sim.py`) と同じで、段・張れる量の関数は `margin_estimate` を共有する。#480 の「感情スコア + F&G・信用の逆張り + 市場ステートの上限 → 目標の維持率」は #594 で比べた版の中で一番悪く、置き換えた ([2026-10-24 の判断記録](../decisions/2026-10-24-運用比率の目標は感情スコアとFGの逆張りで推定維持率から出す.md) は Superseded)。

### 自己資本と倍率

楽天+SBI の合算で、G = 受入保証金、S = 代用になる現物の時価、N = NISA の時価、M = 信用建玉の時価、運用総額 P = S + N + M とする。

- 自己資本 E = G + 0.2 × S + N + 信用建玉の評価益 + C。G は「保証金の現金 + 0.8 × S − 評価損」で評価益を含まないため、その分を足す
- C = 預り金 (保証金とは別)。**SBI だけ**入れる (「現金残高等（合計）− 委託保証金現金」でスィープ口座を含む)。楽天は預り金も受入保証金に入っている (2026-11-26 に画面と突き合わせて確認) ので欄が無く、常に 0。保証金率には効かせず、E にだけ足す。保証金率と一緒にも、預り金だけでも保存できる。空欄なら前回の値を引き継ぎ、次に入れ直すまで一定とみなす。預り金だけを更新した日 (`cash_date`) も、差を `equity_gap` として下落率から外す
- 保証金率は追証の判定に使う率を入れる (SBI は委託保証金率。預り金や受渡前の株も入れた「参考委託保証金率」ではない)。参考の率を入れると、推定維持率と追証までの下落率が甘く出る
- 倍率 = P ÷ E。日次ログに `equity`・`multiple` として残す
- 残高 CSV に保有がある証券会社が1社でも推定できなければ、E も目標も出さない (片方だけで全体を出さない)

### 張りたい量・張れる量・今週の目標

1. **張りたい量** (`want`): ふだん 1.2倍。信用評価損益率の週次の公表値が −15% 以下で、1つ前の公表値より改善した週を**買い向かいの合図**とし、データ日 + 7日 (公表の遅れ) から、最後の合図の3か月後まで 1.6倍 (`boost_until`)。合図が続けば延び、合図のあとに悪化しても取り消さない。日経平均から推した今日の値 (`credit_nowcast`) は表示だけに使う
2. **張れる量** (`cap`): 2.0 × (1 − 口座の高値からの下落率 ÷ 20%)、下限 0.8倍。下落率は日次ログの `equity` を古い順にたどって出す (`drawdown_series`)
   - 高値は更新したときだけ上げる。起点はこのルールを反映した日 (ログに `equity` が出た最初の日)
   - 四半期が変わった最初の行の前で、高値を直前の行の資産に置き換える
   - **入出金**: 入出金履歴は取り込まない。保証金率を入れ直したとき、同じ建玉・終値で旧基準値の推定と新基準値の E の差を基準値の history に `equity_gap` として残す。日次ログの行を作るとき、前の行と比べて基準日 (`margin_by_broker` の `base_date`) が変わった証券会社の `equity_gap` を足して、その行の `equity_gap` に載せ、高値を同じ額だけずらす。手数料・金利も一緒に外れる
3. **今週の目標** (`week_target`): 週は土曜始まり。前の週の最後の行 (ふつうは金曜) の値で、先週の目標から min(張りたい量, 張れる量) へ1段だけ動く (段 0.8 / 1.0 / 1.1 / 1.2 / 1.4 / 1.6 / 2.0)。初回は起点の日の実際の倍率以下で一番高い段を、張れる量で頭打ちにする。土日 (日曜の見直し) には来週の目標が出る
   - 目標は日次ログから毎回計算し直す (別の状態を持たない)。画面も日次ログも、過去のログ行に当日の暫定行を足して計算する (`history_with_today`)

日本版 F&G・感情スコア・市場ステートは量の計算に使わない。表示と日次ログには残す。F&G の Extreme Fear は今日のアクションの「準備」(拾う候補と余力を確かめる)、Extreme Greed は保有の点検 (#589) のきっかけ。感情スコアは日曜に「今週の感情を記録」で促す。

保有銘柄タブでは「張れる量 2.0倍 (口座の高値から −0.0%) · 張りたい量 1.6倍 (買い向かい 〜2/20) → 今週の目標 1.6倍 · いま 1.81倍 · 維持率 54%」と1行に並べ、F&G と信用の区分、感情スコアの記録を参考として後ろに置く。

### 適正エリア

- 目標の運用総額 = 今週の目標 × E。適正エリアはその ±5%。運用総額がエリアより多ければ超過、少なければ不足
- **追証の下限**: 多め側の端は、全保有が一律に 20% 下がっても追証 (20%) にならない建玉 B ≤ (G − 0.8 × 0.2 × S) ÷ (0.2 + 0.2) で頭打ちにし、注記する (#480 と同じ)。増減は信用で行う前提で、減らすときは比例で返済するとみなす
- 保有銘柄の数量から出した運用総額と、残高 CSV の P が 1% 以上ずれたら注記する (判定は P で行う)
- 超過のときは、減らす候補を「防が点いた銘柄・損切り幅を超えた玉 → RS の弱い順」に出す

### 近似の限界

- E は推定維持率と同じ概算。楽天・SBI 以外の証券会社と米国株は入らない。SBI の預り金は入れ直したときの値のまま
- ETF は残高 CSV から position に入り、運用総額・代用・E に入る (issue #605)。ETF は銘柄 DB に終値が無いので、CSV の現在値を使う。次に取り込むまで値は動かない (週1回なら、86万の ETF が5%動いても E の 0.6% ほど)
  - 1保の記録には入らないので、「1保の合計と残高 CSV のずれ」の注記は ETF を除いて比べる
  - 保有銘柄タブでは、「いま ○倍」のツールチップにだけ出す
- 保証金率を入れ直すまでは入出金・手数料・金利を追わない。入れ直した日のずれはまとめて下落率から外す (手数料・金利の損も外れる)
- 返済で評価益が実現して保証金が増える分、現物の売買で掛目の分だけ実際とずれる
- 目標どおりに建玉を動かさなかった週も、目標は先週の目標から動く (#594 の検証は目標どおりに張った前提)

### 成功の基準

2026-12 末の仕様レビュー (#530) で、日次ログ (`exposure_log.json`) から、目標 (`week_target`) と実際の倍率 (`multiple`) の差と、超過 (`position` が over) の日に減らしたかを見る。買い向かいの期間 (`boost_until`) の売買と、口座の下落率 (`drawdown_pct`)・張れる量 (`cap`) の推移も分けて見る。#593 より前の行は、目標の維持率 (`target_rate`・`step`・`step_parts`) のまま残る。判定には使わない参考値として、残高 CSV の建玉の含み損益の合計 (`unrealized_total`・`unrealized_skipped`・`unrealized_as_of`)、証券会社ごとの推定維持率・追証までの下落率・残高 CSV の日付・基準日・推定できない理由 (`margin_by_broker`)、日本版 F&G・信用評価損益率 (最新値・前週値・推定値)・感情スコア・市場ステートも残す。
