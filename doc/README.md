# ドキュメントガイド

現行の動作はコードとテストを優先し、計画書・レビュー資料は作成時点の背景と判断を残す記録として扱います。

## サブフォルダ

| フォルダ | 用途 |
|---|---|
| `spec/` | 現行仕様の詳細: MCP ツール、CLI コマンド、市場ステートの判定 |
| `plan/` | 進行中の機能変更に関する中期の計画・仕様案・将来構想 (下記「計画書の置き場所」) |
| `decisions/` | 長期参照が必要な設計判断と、その理由・トレードオフ |
| `review/` | UI/UX、設計、外部連携などのレビュー・検討資料 (作成時点の記録) |
| `screenshots/` | システム紹介などで長期保管する画像資産 |

## 計画書の置き場所

計画書は有効期間で置き場所を分けます。

| 置き場所 | 置くもの |
|---|---|
| `doc/plan/` (Git 管理) | issue から参照する、または後でまた読む中期の計画。**作成した時点でコミット**し、ファイル名は `issueNNN-内容.md` とする |
| `~/.claude/plans/` (Git 管理外) | Claude Code のプランモードで作る、その実装セッションだけで使う手順。消えても困らないもの |

- プランモードで作った計画を中期の計画にするときは、`doc/plan/` へ**移して** issue からリンクします。`doc/plan/` の計画を元に実装するときは、プランモード側で要約せずにそのファイルを参照します。同じ内容を2か所に持ちません。
- issue が完了したら、現行仕様は正規ドキュメント (アーキテクチャ.md、`spec/` 配下 等) へ、長期参照が必要な判断は `doc/decisions/` へ移し、計画書は削除します。これを PR の完了条件とします。削除した計画書は Git 履歴から参照できます。
