# ドキュメントガイド

このディレクトリには、Shintakane の利用・運用・設計に関する文書を置きます。
現行の動作はコードとテストを優先し、計画書・レビュー資料は作成時点の背景と判断を残す記録として扱います。

## 主要ドキュメント

| 文書 | 用途 |
|---|---|
| [システム概要](システム概要.md) | システムの目的、機能、スコアリングの概要 |
| [ARCHITECTURE.md](ARCHITECTURE.md) | データフロー、DB、パス解決などの技術構成 |
| [COMMANDS.md](COMMANDS.md) | 開発・運用コマンドの一覧 |
| [OPERATIONS.md](OPERATIONS.md) | 運用機と開発機の役割、定常運用手順 |
| [TESTING.md](TESTING.md) | テスト方針と実行方法 |
| [MCP.md](MCP.md) | 提供中のMCP、制約、接続・運用への入口 |
| [用語集と不変条件](用語集と不変条件.md) | 用語の定義と、機能をまたぐ制約 (AI が実装前に必ず読む) |
| [AI開発原則](AI開発原則.md) | AI と開発するときに文書へ何を書くか、開発での AI の使い方 |
| [AI投資活用戦略](AI投資活用戦略.md) | 投資判断での AI の使い方 (Shintakane / LLM / 人間の分業) |

## サブフォルダ

| フォルダ | 用途 |
|---|---|
| `plan/` | 進行中の機能変更に関する中期の計画・仕様案・将来構想 (下記「計画書の置き場所」) |
| `decisions/` | 長期参照が必要な設計判断と、その理由・トレードオフ |
| `requirements/` | 正規ドキュメントから参照される、現行仕様の詳細 |
| `review/` | UI/UX、設計、外部連携などのレビュー・検討資料 (作成時点の記録) |
| `screenshots/` | システム紹介などで長期保管する画像資産 |

## 計画書の置き場所

計画書は有効期間で置き場所を分けます。

| 置き場所 | 置くもの |
|---|---|
| `doc/plan/` (Git 管理) | issue から参照する、または後でまた読む中期の計画。**作成した時点でコミット**し、ファイル名は `issueNNN-内容.md` とする |
| `~/.claude/plans/` (Git 管理外) | Claude Code のプランモードで作る、その実装セッションだけで使う手順。消えても困らないもの |

- プランモードで作った計画を中期の計画にするときは、`doc/plan/` へ**移して** issue からリンクします。`doc/plan/` の計画を元に実装するときは、プランモード側で要約せずにそのファイルを参照します。同じ内容を2か所に持ちません。
- issue が完了したら、現行仕様は正規ドキュメント (ARCHITECTURE.md / COMMANDS.md / MCP.md 等) へ、長期参照が必要な判断は `doc/decisions/` へ移し、計画書は削除します。これを PR の完了条件とします。削除した計画書は Git 履歴から参照できます。
