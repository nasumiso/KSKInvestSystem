# 用語集と不変条件

名前から意味が推測できない用語と、機能どうしの間に張られた制約をまとめる。
AI (と未来の自分) がコードから推測できず、勝手に解釈すると「正しく動くが意図と違うもの」ができる部分だけを書く。
書き方の方針は [AI開発原則.md](AI開発原則.md) を参照。

## 用語集

### 保有と売買

| 用語 | 定義 |
|---|---|
| `1保` / `2準` / `3監` | 保有ステータス。1保 = 保有中、2準 = 準保有 (買う準備ができている。売却後もここに戻る)、3監 = 監視。値はこの3つだけ |
| 売買戦略 (`trade_idea`) | 銘柄に**入るときの意図**。結果の保有期間ではない。戦略マスターに登録された名前だけを使う。戦略マスターの `exit_rule` が防衛線の定義元。各戦略の定義 (説明文) の正本も戦略マスター (DB、編集画面で変える) で、コードの初期値は空の DB 用 |
| ロット | エピソードの中で買い増し・別意図の玉を区別する単位。文脈で2つの指し方がある: 戦略の付与 (`fill_strategy`) では**建て側の fill 1件ごと** (`seq` キー)、保有の点検 (`portfolio_review.open_lots`) では**往復行のうち未決済の行** (`open_seqs` 単位。損切り幅・時間軸の超過判定はこの単位で行う)。`fill` (約定1件) / `エピソード` (現物・信用ごとの 0→建→0) / `往復行` (買→売1組) / `保有サイクル` (現物+信用の合算保有期間) とは別の単位 |
| ロットの戦略 | 建て側の fill (買い・信用新規・現引) に付ける戦略。エピソードの戦略と違うロットにだけ付け、無ければエピソードの戦略に従う。**買った時点の意図**で付ける。中核の玉とは別に「戻りで売るつもりで買った」押し目買いのロットは中期底値リバにする。中核に足すつもりで買い、結果的に早く売ったロットは中核の戦略のまま (保有日数の短さでは分けない) |
| fill | 証券会社の取引履歴CSVにある約定1件。約定事実そのもの |
| エピソード (建玉ラウンド) | 銘柄 × 現物/信用 ごとに、建玉が 0 → 建 → 0 に戻るまでの1サイクル。現引は信用から現物へ振り替えて現物側に合流する。キーは `code_s|kind|first_seq` |
| 保有中エピソード | 売却側の約定がまだ無いエピソード。**実際の保有とは一致しない** (売却の約定が取り込まれていない銘柄も残る)。保有銘柄数・保有構成は 1保 で数える (`portfolio_list.py --status 1保`)。損益の集計は fill 側で行う |
| 往復行 | エピソード明細を「買→売」1行に畳んだ単位。信用は返済の建約定日、現物は FIFO で組む。現物は買いロットと売りを手で結びつけられ (`lot_match`)、その組を先に使って残りを FIFO で組む。現引で現物化した玉は、現物側でも買った日を信用の建日にする (単価は現引の取得単価のまま)。**戦略別の成績の母数** (クローズ済みエピソードの決済済みの行を、建てロットの戦略で集計する)。キーは持たず、集計・表示のたびに作る (遡り取込で組が変わるため)。現引の行は損益を持たないので数えない |
| SBI返済の推定建玉 | CSVに建情報が無い場合、諸経費・税額込みの決済損益が一致する、同社・返済日以前の残建玉が1本で返済数量を満たすときだけ往復行に建日・建値を補完する。同単価の別ロットなど候補が複数なら建玉不明のまま。補完値はfillの建情報には保存せず、決済損益はCSVの値を使う |
| 保有サイクル | 銘柄の保有株数 (現物+信用) が 0 にならない限り続く期間。防歴の同一性判定に使う。エピソードとは別物 |
| action_log | 「なぜそうしたか」を残す判断の記録。追記のみ。`timestamp` は入力日時ではなく**売買日** |
| covered | CSV取込で、その銘柄に関わる全ソース (楽天・SBI の現物/信用) が揃っている状態。covered でない銘柄は判定不能として更新しない |
| 早売 / 防 / 防歴 | 早売 = 10MA の violation 確定。防 = 戦略ごとの MA (50MA/30WMA/40WMA) の violation 確定、または損切り線割れ。防歴 = 保有サイクル内で防が出た事実。1保 → 2準 (売却) のときだけ記録を残し、準保有では損切り線なしで MA だけを判定する。それ以外の遷移 (2準 → 1保 の買い直しを含む) では消える。MA回復 = MA 割れ確定の防のあと、MA (保有なら損切り線も) の上に戻った日 (#526) |
| ブ / ブ+ / 週ブ | ブ = 出来高が30日平均の1.5倍以上 (またはストップ高) で上げた日のうち、終値が直前20日の終値の高値を上抜け、週足のステージ2 (中核3条件) と52週の範囲 (高値の25%以内・安値の1.3倍以上) を満たすもの。ブ+ = ブのうち、直前10日の値幅が前日終値の10%未満で、出来高が平均の2倍以上。条件から外れた出来高急増は詳細チャートに中抜きの◇でだけ出す。週ブ = 出来高の閑散 → 5日間の拡大 → 20日高値の上抜け。検知 (`price.py`) は生のまま残し、出すかどうかは解釈層 (`make_stock_db.extract_signals` / `make_signal`) で決める ([判断記録](decisions/2026-11-12-ブは本来のブレイクアウトの条件で出す.md)) |
| タグ略号 (`月破`・`高/出/P`・`売/警`・`急/昇`) | 判定と閾値の正本は `make_stock_db.make_signal` / `judge_monthly_position` (tooltip 理由も同じ箇所で生成)。名前から誤解しやすいものだけ挙げる: **`月破 / 月高 / 月低`** = 10年レンジでの月足位置 (相互排他、優先度は `月破 > 月高 > 月低`。`月破` は長期の低位滞留から直近3ヶ月以内に3年高値を上抜け、現値がまだ低〜中位の銘柄)。**`高 / 出 / P`** = 当日〜前日の株探リスト掲載由来 (新高値 / 出来高急増 / PTS) で、銘柄DBの計算結果ではない。**`売 / 警`** = 強かった銘柄 (高 `rs_raw`) が弱り始めた警戒サイン (売り圧力比率20日悪化・週足10MA割れの両方で `売`、片方で `警`。出口ラインの `防` とは別物)。**`急 / 昇`** = 総合順位が前日比 (`急`) / 5日前比 (`昇`) で急上昇した印 (最新営業日のログがある銘柄のみ) |
| ステージ | ミネルヴィニのステージ (1S 底固め / 2S 上昇 / 3S 天井圏 / 4S 下降)。人がチャートを見て付ける (`memo.stage`、遷移 `A~B` とベース番号付き)。定義は典型像で、境目の数値は決まっていない。本人の境目の見方: 4S は30・40週線が下を向くのを待たず、一直線に落ちていれば付ける。ただし直近安値からの下げ幅が小さいうちは 3S。上昇後の横ばいでも、期間が長ければ天井圏ではなく新しいベース (1S)。変更は `stage_history` に残る (値を変えた `change`、見直して据え置いた `confirm`) |
| LLM のステージ | 保有の週足チャートを LLM に読ませた第二意見 (#580、`stage_llm`)。人のラベルとステージ番号が重ならず、人がその後に見直していないときだけ「不一致」として知らせる。1回の読み取りには揺れがあり、断定ではない |
| `strategy_drift` / `split_suspect` | 集計母数から外すためのエピソードの状態フラグ (エラーではない)。`strategy_drift` = クローズ確定時に焼いた fill の `seq` 指紋が遡り取込等で変わった状態 (または指紋があるのに未決済に戻った状態)。戦略別集計・損切り幅超過判定から除外し「要再確認」とする。`split_suspect` = 未登録の分割・併合の疑い、または登録済み分割をまたぐ未決済の信用エピソード等。エピソード損益・往復行集計・保有の点検の母数から除外する (拒否リストで明示解除しない限り残る) |
| 保有の点検 / 月次の売買振り返り | どちらも振り返りの仕組みだが対象と粒度が違う。**月次の売買振り返り** (`/trade-review`、`trade_review/`) は決済済みの売買をエピソード単位で毎月振り返る。**保有の点検** (`/portfolio-review`、`portfolio_review/`) は保有中の建玉をロット単位で仕分け、定期実行せずきっかけ (新しい「防」・幅超えロット増・市場ステート悪化・推定維持率低下) が起きたときだけ行う。市場ステートが調整に入ったときは逆指値・線に近い玉・新規買いの約束・維持率で売る順番も確認する (**調整入りの点検**)。点検で「持つ」を選んだときの**約束 (売る条件)** は次回点検で照合するだけで、日次の「防」の判定には混ぜない |
| 運用比率 (エクスポージャー) | 運用総額 (現物時価 + NISA + 信用建玉の時価) が適正エリア (今週の目標の倍率 × 自己資本 ±5%) の中にあるか (#593)。楽天・SBI のどちらかが推定できない日は出さない。日本版 F&G・感情スコア・市場ステートは量の計算に使わない |
| 倍率 / 自己資本 | 倍率 = 運用総額 ÷ 自己資本。自己資本 = 受入保証金 + 0.2 × 代用の現物 + NISA + 信用の評価益 + 預り金 (`outside_cash`) (推定維持率と同じ推定から出す概算) |
| 預り金 (`outside_cash`) / `equity_gap` | **預り金 (`outside_cash`)** = 保証金とは別の現金。**SBI だけ**手入力し (楽天は預り金も受入保証金に入るため常に 0)、保証金率には効かせず自己資本にだけ足す。**`equity_gap`** = 入出金履歴を取り込まない代わりに、保証金率や預り金の入れ直し時に旧推定と新自己資本の間に生じた差額を基準値履歴と日次ログに残し、口座高値を同じ額だけ平行移動させて下落率から外す補正額 (手数料・金利のずれも一緒に外れる) |
| 張りたい量 / 張れる量 / 今週の目標 | 張りたい量 = ふだん 1.2倍、買い向かいの合図が出たら最後の合図から3か月 1.6倍。張れる量 = 2.0 × (1 − 口座の高値からの下落率 ÷ 20%)、下限 0.8倍 (高値は更新時のみ上げ、四半期末に置き換え、`equity_gap` 分をずらす)。今週の目標 = 小さい方へ、先週の目標から週1段 (0.8 / 1.0 / 1.1 / 1.2 / 1.4 / 1.6 / 2.0)。週は土曜始まりで、日次ログから毎回計算し直す (状態を持たない)。VI で抑える週は例外的に即 0.8倍にする |
| VI で抑える (`week_vi_hold`) | 暴落のテールを避けるため、判定日 (前週の最終行) の日経VI が 30 を超えたら 25 を下回るまで今週の目標を **0.8倍まで**に抑える (#610)。25〜30 は前の状態を維持する (ヒステリシス)。抑えるときは週1段ではなくその週に 0.8倍へ下げ、外れたら週1段で戻す。買い向かい期間 (1.6倍の3か月) は抑えず、2026-11-27 より前の判定日には遡及適用しない |
| 信用評価損益率 (3系統) / 買い向かいの合図 | 名前が同じ3系統があり役割が違う。**週次の公表値** (`credit_balance.json`) = 判定に使う唯一の値。**`credit_nowcast`** = 日経平均の動きから推す当日値 (表示のみ)。**`credit_daily_est`** = JPX 銘柄別信用残からの日次推計 (#600、公表値との誤差検証中・表示のみ)。**買い向かいの合図** = 週次の公表値が −15% 以下かつ前週より改善した週。データ日 + 7日 (公表の遅れ) から3か月間、張りたい量を 1.6倍にする (途中で悪化しても取り消さない) |
| 感情スコア | 自分の相場観・心理を手入力で記録する値 (日曜の見直しで記録)。旧仕様 (#480) では運用比率の計算に使っていたが #593 で量の計算からは外し、現在は表示と日次ログの記録だけに残す |
| 推定維持率 | 楽天・SBI の信用の保証金率の概算。ユーザーが入れた保証金率を基準値に、残高 CSV の建玉と株価から差分で出す。証券会社が表示する公式の値ではない ([仕様](spec/推定維持率仕様.md)) |

### 評価とスコア

**2つの別物に同じ言葉が使われている**ので注意する。

| 用語 | code_rank (総合ポイント) | 銘柄評価台帳 (stock_ratings) |
|---|---|---|
| 何か | 日次バッチが全銘柄に機械的に付ける点数。フィルタ・監視に使う | ChatGPT との分析で付ける投資判断。株価で変わる2軸はシステムが毎日出す (採点ルール Ver3) |
| 構成 | 業績40% / モメンタム25% / 指標20% / テーマ人気15% | ファンダ40 / 未織込20 (AI) + Valuation20 / モメンタム20 (システム) |
| 「ファンダ」の意味 | 使わない。旬のテーマの点は「テーマ人気」(15%) と呼ぶ (2026-11 に「ファンダメンタル」から改名、#546) | **業績加速・利益可視性・構造成長・質** (40点) |
| 「モメンタム」の意味 | 株価モメンタムの分布上の位置 | 個別の RS (`momentum_pt` ÷ 10) + 業態テーマ順位。基準日の値だけを使う |

両者は統合しない。役割と各軸が測るもの・測らないものは [spec/銘柄評価仕様.md](spec/銘柄評価仕様.md)。

| 用語 | 定義 |
|---|---|
| 未織込 | **今わかっている数字 (会社予想・四季報予想) と、これから出る数字の差** (採点ルール Ver3)。株価の水準・PER・騰落・決算後の株価反応は見ない (それは Valuation とモメンタムの領分)。Ver2 では「市場がまだ十分評価していないか」で、割安さと重なっていた |
| 適正株価 (`fair_price`) | 評価台帳で AI が付ける、中期で妥当と考える株価 (円)。手法は問わない。システムが基準日の終値と比べて Valuation の点にする |
| 基準日 (評価台帳) | 業態テーマ順位の最新記録日。台帳の Valuation とモメンタムは、この日の終値と RS だけを使う。株価がこの日のものでない銘柄は「欠」 |
| Confidence (A/B/C) | 将来の数字をどれだけ推定できるか。C はオプション価値中心で、ポジションサイズに注意 |
| Status (Active/Watch/Archive) | 評価台帳上の扱い。Active = 仮説が生きていて持っている・入る準備ができている、Watch = 仮説はあるが確認待ち、Archive = 仮説崩れ・時間切れ・見送り (比較の対象外)。保有ステータス (1保/2準/3監) とは連動させず、制約だけを置く (下の不変条件) |
| 決算直後の未更新 / 古くなった評価 (評価台帳) | 評価台帳の鮮度2区分 (トップの「今日のアクション」でも別行。Active と Watch でルールが違う。[spec/銘柄評価仕様.md](spec/銘柄評価仕様.md))。**決算直後の未更新** (表示名「決算後の台帳更新」) = 直近の決算発表当日〜14日以内に台帳が未更新 (Active は銘柄名、Watch は件数+ポップアップ)。**古くなった評価** (表示名「台帳の更新待ち」) = Active は直近の決算発表日から14日超未更新、Watch は最後の更新から決算を2回またいだ銘柄 (Watch は14日を過ぎると直後表示が消え、2回またぐまで更新待ちに出ない) |
| 総合点 (評価台帳) | 企業価値のランキングではなく、**現在価格からの中期投資魅力度** |
| RSスコア（0〜100） | 銘柄の `momentum_pt`。銘柄とTOPIXの `rs_raw` の比を分布モデルで0〜100に点数化した値。銘柄を並べた実順位ではない |
| 市場RS（倍率） | 市場指数の `rs_raw`。現在価格を13・26・39・52週前の価格で割った倍率を40%・20%・20%・20%で加重平均する。履歴不足時は取得できる期間の重みを再配分する。TOPIXとの比較ではない |
| RSライン（対TOPIX） | 銘柄終値 / TOPIX終値。詳細チャートの左軸は表示窓の基準週を0%にした変化率。RSスコアとは別の尺度 |
| RSラインの A / B (`compute_rs_line_changes`) | RSライン (銘柄終値 / TOPIX終値) の今日の値と、直近5日 (A)・20日 (B) **平均との乖離率**。N日前の1点との比ではない (#283 で変更)。D (前日比) だけは1点比較。code_rank のモメンタム列、銘柄詳細の tooltip、業態テーマ別サマリーが同じ定義を使う |
| 6ヶ月相対 | 銘柄の (今の終値 / 26週前の週末終値) を、TOPIX の同じ比で割って1を引いた値。26週前は週足の位置ではなく週で引く。銘柄には価格だけの比 (`chg_26w`) を保存し、TOPIX で割るのは集計時 (#531) |
| テーマ順位 | 業態テーマごとの6ヶ月相対の等加重平均で付けた順位。日次バッチが毎日記録し、業態テーマ別サマリーが3週前・6週前と並べる。記録はその日の分類のまま残り、テーマの付け替えをさかのぼらない。`momentum_pt` の平均とは別物 |

### 時間とデータ

| 用語 | 定義 |
|---|---|
| 価格日 | 17時前は前日扱い (`ks_util.get_price_day`)。場中の値で当日を語らない |
| `period` (四季報) | 四季報の版情報。データ時点ではない (`as_of` は null) |
| 来季予想 (四季報) | 2期先で不確実性が高い。成長シナリオを読む定性材料 |
| 業績のタグ `<収利率>` | 業績表現の末尾に付く、直近3四半期の成長の型 (`gyoseki.calc_growth_tags`)。収 = 売上 (増収) の前年同期比が3期続けて加速、利 = 営業利益の前年同期比が3期続けて加速 (前年同期が黒字のときだけ)、率 = 3期とも営業利益率が前年同期より高い。3つそろいが Minervini の Code 33。ポートフォリオ表示だけに使い、スコアには入らない。売上を「売」にしないのは、タグ列の「売」(売りシグナル) と紛れるため |
| テーマ | 株探テーマ (市場データ・テーマランク) と業態テーマ (保有銘柄の事業分類) の2系統があり、無関係 |

## 不変条件

### システム

| 不変条件 | 破るとどうなるか | 守る場所 |
|---|---|---|
| 銘柄コードは常に文字列 (`code_s`) | 先頭の 0 が落ちる、`215A` 形式を扱えない | 全層 (コーディング規約) |
