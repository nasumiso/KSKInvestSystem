# 用語集と不変条件

名前から意味が推測できない用語と、機能どうしの間に張られた制約をまとめる。
AI (と未来の自分) がコードから推測できず、勝手に解釈すると「正しく動くが意図と違うもの」ができる部分だけを書く。
書き方の方針は [AI開発原則.md](AI開発原則.md) を参照。

## 用語集

### 保有と売買

| 用語 | 定義 |
|---|---|
| `1保` / `2準` / `3監` | 保有ステータス。1保 = 保有中、2準 = 準保有 (買う準備ができている。売却後もここに戻る)、3監 = 監視。値はこの3つだけ |
| 売買戦略 (`trade_idea`) | 銘柄に**入るときの意図**。結果の保有期間ではない。戦略マスターに登録された名前だけを使う。戦略マスターの `exit_rule` が防衛線の定義元 |
| fill | 証券会社の取引履歴CSVにある約定1件。約定事実そのもの |
| エピソード (建玉ラウンド) | 銘柄 × 現物/信用 ごとに、建玉が 0 → 建 → 0 に戻るまでの1サイクル。現引は信用から現物へ振り替えて現物側に合流する。キーは `code_s|kind|first_seq` |
| 往復行 | エピソード明細を「買→売」1行に畳んだ表示単位。**集計の母数にはならない** |
| 保有サイクル | 銘柄の保有株数 (現物+信用) が 0 にならない限り続く期間。防歴の同一性判定に使う。エピソードとは別物 |
| action_log | 「なぜそうしたか」を残す判断の記録。追記のみ。`timestamp` は入力日時ではなく**売買日** |
| covered | CSV取込で、その銘柄に関わる全ソース (楽天・SBI の現物/信用) が揃っている状態。covered でない銘柄は判定不能として更新しない |
| 早売 / 防 / 防歴 | 早売 = 10MA の violation 確定。防 = 戦略ごとの MA (50MA/30WMA/40WMA) の violation 確定、または損切り線割れ。防歴 = 保有サイクル内で防が出た事実 |
| 運用比率 (エクスポージャー) | 運用総額に対する保有額の比率。市場ステートから目標レンジを出す。過熱指標は上限を削る方向にだけ効く |

### 評価とスコア

**2つの別物に同じ言葉が使われている**ので注意する。

| 用語 | code_rank (総合ポイント) | 銘柄評価台帳 (stock_ratings) |
|---|---|---|
| 何か | 日次バッチが全銘柄に機械的に付ける点数。フィルタ・監視に使う | ChatGPT との分析で付ける、現在時点の投資判断のスナップショット |
| 構成 | 業績40% / モメンタム25% / 指標20% / ファンダ15% | ファンダ40 / 未織込20 / モメンタム20 / Valuation20 |
| 「ファンダ」の意味 | **旬のテーマ** (15%) | **業績加速・利益可視性・構造成長・質** (40点) |
| 「モメンタム」の意味 | 株価モメンタムの分布上の位置 | 決算後反応・相対強度・出来高と値持ち |

両者は統合しない (#456)。

| 用語 | 定義 |
|---|---|
| 未織込 | 良い材料があるかではなく、**その良さを市場がまだ十分評価していないか** (市場認識との差)。良い会社でも織り込み済みなら低い |
| Confidence (A/B/C) | 将来の数字をどれだけ推定できるか。C はオプション価値中心で、ポジションサイズに注意 |
| Status (Active/Watch/Archive) | 評価台帳上の扱い。保有ステータス (1保/2準/3監) とは連動しない |
| 総合点 (評価台帳) | 企業価値のランキングではなく、**現在価格からの中期投資魅力度** |
| RSラインの A / B (`compute_rs_line_changes`) | RSライン (銘柄終値 / TOPIX終値) の今日の値と、直近5日 (A)・20日 (B) **平均との乖離率**。N日前の1点との比ではない (#283 で変更)。D (前日比) だけは1点比較。code_rank のモメンタム列、銘柄詳細の tooltip、業態テーマ別サマリーが同じ定義を使う |

### 時間とデータ

| 用語 | 定義 |
|---|---|
| 価格日 | 17時前は前日扱い (`ks_util.get_price_day`)。場中の値で当日を語らない |
| `period` (四季報) | 四季報の版情報。データ時点ではない (`as_of` は null) |
| 来季予想 (四季報) | 2期先で不確実性が高い。成長シナリオを読む定性材料 |
| テーマ | 株探テーマ (市場データ・テーマランク) と業態テーマ (保有銘柄の事業分類) の2系統があり、無関係 |

## 不変条件

### システム

| 不変条件 | 破るとどうなるか | 守る場所 |
|---|---|---|
| 銘柄コードは常に文字列 (`code_s`) | 先頭の 0 が落ちる、`215A` 形式を扱えない | 全層 (コーディング規約) |
| shelve への書き込みは提供 API 経由のみ。並行書き込みしない | DB 破損 | `ShelveDB` の flock (`db_shelve.py`) |
| 開発機は正本データに書かない | 古いデータで正本や Drive 出力を上書きする | `KS_DATA_DIR` の `_dev` 判定、`shintakane_cron.sh` の即 exit (#453) |
| CSV取込が上書きするのは `qty` と `status` だけ。売買戦略・メモ・action_log は上書きしない | 人が書いた判断が消える | `import_portfolio_csv.py` |
| 1保 にするには売買戦略が要る | 出口ルールのないポジションができる | WebApp の遷移 (`routes/portfolio.py`)、CSV取込の自動IN判定。**`portfolio_shelve.transition_status` 自体では守っていない** |
| fill は変更しない。分割・併合の換算は作業用コピーに対して行い、現物だけに適用する | 約定事実が失われる、信用の確定損益と二重にずれる | エピソード再構成 (`webapp/trade_episodes.py`) |
| 売買戦略はエピソードにコピーして保存する。銘柄の現在の戦略を参照しない | 同じ銘柄に別戦略で入り直すと過去の成績が書き換わる | `episode_strategy` (`portfolio_shelve.py`) |
| 損切り線はエピソード単位で計算し、常に取得単価以下 | 決済済みの旧建玉の原価を引きずり、含み益の建玉に防が出る | `exit_line.py` |
| 評価台帳への書き込みは `stock_ratings.py` 経由だけ。更新理由が必須で、変更は履歴に追記される | 検証と履歴を迂回した値が入る | `stock_ratings.py`、MCP の `update_stock_rating` |
| 決算スナップショットの手書き (`ir_comment`) と `data_source` のラベルは、同日の自動追記で上書きしない (自動生成の項目は上書きする) | 手で書いた調査資産が消える | `research_shelve._merge_snapshot` |
| 中計の `is_latest` は自動で落とさない | 推定日付で古い計画を最新扱いし、正しい資料を隠す | `ir_docs.py` |
| 業態テーマ名の追加・変更・削除はテーママスター (`/portfolio/themes`) だけで行う。銘柄に新しく付けられるのは登録済みの名前だけ (登録前から付いている値は保持できる)。リネーム・削除は同じロックの中で全銘柄のメモに反映する | 同義語・誤字でテーマ別サマリーの集計が割れる。途中で失敗すると銘柄とマスターが食い違う | `portfolio_shelve.update_memo` / `update_theme` / `delete_theme` |

### 投資判断

評価台帳の採点ルール、[AI投資活用戦略.md](AI投資活用戦略.md)、[方向性メモ.md](方向性メモ.md) から起こし、2026-09-27 に確定した。「状態」は現在の実装状況で、未実装でもルールとしては有効。

| 不変条件 | 破るとどうなるか | 守る場所 | 状態 |
|---|---|---|---|
| 最終投資判断・サイズ・時間軸は人が決める。AI の分析は材料であって結論ではない | AI に従って間違える方が楽、という構造に流れる | 運用 (MCP は推奨・売買をしない) | 運用で守る |
| 数値は一次ソースと Shintakane から取り、LLM は解釈に使う | ハルシネーションが数値に混ざる | 運用、MCP の返却データ | 運用で守る |
| 保有状況や自分の仮説を評価台帳の総合点に加点しない | 確証バイアスが点数に入る | 採点ルール (`update_stock_rating` の説明) | 実装済み |
| 強い上昇はモメンタムで加点し、織り込みの進展は未織込・Valuation で反映する。急騰を二重に減点しない | 強い銘柄を点数だけで早売りする | 採点ルール | 実装済み |
| 新規INのスコアと保有継続の判断を分ける | 低スコア化だけで強い保有株を機械的に売る | 採点ルール | 実装済み |
| AI には買う理由と同じ詳細さで買わない理由を出させる | 問い方で見たい答えを引き出す | プロンプト (運用) | 運用で守る |
| 評価を更新するとき、前回の仮説を消さず、補強・反証・未確認に分けて比べる | 仮説がいつの間にか入れ替わる | 評価台帳の履歴 (差分は残るが、比較は未実装) | 一部実装 |
| 見送りも判断として残す | 見送った銘柄の結果から学べない | 未実装 | 未実装 |
