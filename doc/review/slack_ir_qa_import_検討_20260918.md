# Slack から IR問い合わせ回答を自動取り込みする構想の検討 (2026-09-18)

## 結論

**自動化は成立しない。手動コピペ運用 (#436 のフォーム) を継続する。**

Slack メッセージから「どの銘柄の、いつの回答か」を機械的に判定できないため。運べるのはテキストを inbox に落とすところまでで、そこから先が全部手作業になる。それなら Slack から直接コピペするのと変わらず、inbox の管理コストだけが増える。

## 発端

IR部門への問い合わせ回答が、ユーザーの参加する Slack チャンネルに投稿される。これを取得して WebApp (#436 で実装した `ir_qa`) へ登録するフローが組めないか、という検討。

## 前提の訂正: Claude Code は Slack と連携していない

- 存在するのは **Claude Tag (Claude in Slack)** — Slack 上で `@Claude` に話しかけて会話する機能
- Slack 上の Claude は Anthropic のサーバーで動くので、**ローカルの WebApp や DB には触れない**
- 逆にローカルの Claude Code セッションには Slack ツールが無い (MCP は playwright / serena / shintakane-shikiho のみ)
- 両者は繋がっていないので「Slack の Claude が読んでローカルに登録する」経路は存在しない

## Slack 側の権限制約

ユーザーはワークスペースの**一般参加者**で、管理者への依頼は困難。

インストール済みアプリ: `Claude`, `Notion`, `ChatGPT`, **`Make`**

| 方式 | 可否 | 理由 |
|---|---|---|
| Bot Token (`xoxb-`) + Slack MCP | ✕ | App 作成・スコープ付与・インストールが管理者権限 |
| User Token (`xoxp-`) | △ | 権限が通っても、他人のワークスペースにアプリを入れるのは筋が悪い |
| cron 自動取り込み | ✕ | 上記が前提なので同じく不可 |
| ブラウザ自動化 (Playwright で Slack Web を読む) | △ | 動くが DOM 変更の保守コスト・規約リスク。Kabutan スクレイピングと同じ保守負債 |
| **Make 経由** | ○ (技術的には) | 管理者依頼不要。ただし後述の判定問題で頓挫 |

## Make 経由の構成 (技術的には成立した案)

Make はクラウドなので飛ばし先が `localhost:5001` だと届かない。**Google Drive を中継**すれば公開エンドポイント不要で成立する (このプロジェクトは既に `googledrive.py` / `KS_DATA_DIR` で Google Drive を使用)。

```
Slack (IR回答投稿)
  → Make: Watch Messages トリガー
  → Make: Google Drive にテキストファイル作成 (ir_inbox/xxx.txt)
  → ローカル: cron or 手動で inbox を読んで add_ir_qa
```

- 公開エンドポイント不要 (`ngrok` 等で WebApp を晒す案1は認証が無いので却下)
- Make 無料プラン (1,000オペレーション/月) で足りる
- Make 側で吸収できる: 対象チャンネル限定、特定ユーザーのみ、投稿日時 (`ts`) 取得、絵文字リアクションをトリガーにする

## 頓挫した理由: 実メッセージが機械判定に向かない

実サンプル2件 (マルマエ / サムコ) で検証した結果、4つすべてで人の判断が必要だった。

### 1. 銘柄コードが本文に無い

社名だけが書かれている。`search_stocks` で社名→コード解決はできるが、IR回答は**失うと再取得できないエッジ情報**なので、誤登録が実害を持つ。短い社名や部分一致で複数候補が出る社名で誤爆リスクが残る。

| 投稿 | 銘柄名 | コード | 問題 |
|---|---|---|---|
| 22:56 | マルマエ | 6264 | 本文に無し |
| 23:38 | `サムコ(既出)` | 6387 | 「(既出)」が混入 |

### 2. 1メッセージに複数の回答日が混在

マルマエの投稿は 1 メッセージ内に時期が2つ入っており、`ir_qa` の仕様 (1エントリ = 1回答日) では**2エントリに分割すべき**。

```
マルマエ
2026年4月当初   ← 回答日が違う
  １．〜４．
2026年8月       ← 回答日が違う
  Q①〜Q④
```

### 3. 回答日を日単位で確定できない

見出しが「2026年4月当初」「2026年8月」で、**日が無い**。`answered_at` は `YYYY/MM/DD` なので日を補完するしかないが、勝手に決められない。
→ [年省略日付の年を仮定で補完しない] の同類問題。

### 4. 投稿日 ≠ 回答日

4月の回答を8月以降にまとめて転記している。Slack の `ts` を `answered_at` に使えない。

### 補足: 設問記法も投稿ごとに違う

本文はそのまま保存する仕様なのでパースは不要だが、**自動分割の手がかりには使えない**。

| 投稿 | 設問 | 回答 |
|---|---|---|
| マルマエ 4月 | `１．２．３．４．` (全角数字) | `⇒` |
| マルマエ 8月 | `Q①〜Q④` | `A①:` |
| サムコ | `①②③` | `Ａ：` (全角A) |

## 採用した運用

**#436 のフォームに手動コピペ。** 実測1分程度 (SHIFT の 2274文字・27行で確認済み)。

判断が必要な部分だけユーザーが決めて、分割・整形・登録を Claude に頼む分担も可能 (新規実装ゼロ、`POST /stock/<code>/ir_qa` をそのまま使う):

> マルマエ 6264、4月分は 2026/04/01、8月分は 2026/08/XX で登録して

## 再検討する条件

- IR回答が**週に数件以上**流れてくるようになった (現状は知り合い経由で不定期、月1〜2件程度)
- 投稿フォーマットが安定した (銘柄コード併記・1投稿1回答日・日付が YYYY/MM/DD)
- 管理者に Bot Token を相談できる状況になった (必要なのは読み取り専用の `channels:history` または `groups:history` + チャンネルへの Bot 招待のみ)

なお 2026-H2 は機能追加凍結フェーズ (実装対象は issue #360-#367) なので、この構想は範囲外。再開するなら方針の例外として明示的に判断する。
